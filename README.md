# Phalanx Headquarters · 마케도니아 원정군 사령부

Windows Godot 4.7.2용 3D 사령부 프로토타입입니다. 사람 눈높이의 1인칭 시점으로 지휘 천막 안과 가까운 야영지를 걸어 다니며, 작전 테이블에 접근해 기존 2D 투자 대시보드를 엽니다. 해질녘 조명 아래 처진 천막과 먼 야영지를 배치하고, 목재·천·청동·양피지·흙은 서로 다른 절차적 셰이더 재질을 사용합니다. 메시와 재질을 프로젝트 안에서 생성하므로 외부 에셋이나 추가 패키지가 필요하지 않습니다.

**모든 가격·차트·분석 문구·점수·계좌·매매계획은 UI 검증용 가상 데이터입니다.** 실시간 시세, 실제 계좌, 주문 기능, 기존 Python 투자 엔진은 연결되어 있지 않습니다.

## 실행

Godot에서 `project.godot`를 가져와 열고 **F5**로 실행합니다. 시작 씬은 `scenes/command_camp.tscn`입니다. 기존 대시보드는 `scenes/headquarters.tscn`을 열고 **F6**으로 독립 실행할 수 있습니다.

설치된 Windows 실행 파일을 사용하는 PowerShell 예시입니다.

```powershell
$godot = 'C:\Users\hanso\Tools\Godot\Godot_v4.7.2-stable_win64.exe'
& $godot --path .
```

위 명령은 프로젝트 폴더에서 실행합니다. 요청에 표기된 `Godot\_v4.7.2-stable\_win64.exe` 경로 대신, 실제 확인된 `Godot_v4.7.2-stable_win64.exe` 파일을 사용합니다. 한글은 Windows의 맑은 고딕 등 운영체제 글꼴을 사용하며 별도 글꼴 파일을 배포하지 않습니다.

## 조작

- 처음 표시되는 **클릭하여 탐색 시작** 안내에 따라 게임 화면을 클릭합니다. 마우스가 캡처되면 **WASD**로 이동하고 **마우스**로 시선을 돌립니다. 점프·달리기·머리 흔들림은 없습니다.
- 화면 중앙의 조준점을 작전 테이블에 맞추고 가까이 가면 강조와 **E — 작전 테이블 열기** 안내가 나타납니다. **E**를 눌러 대시보드를 엽니다. 벽이나 물체에 가려지거나 너무 멀면 선택되지 않습니다. 왼쪽 클릭은 탐색 시작에만 사용합니다.
- 탐색 중 **Esc**는 마우스를 해제하고 이동·시선 입력을 멈춥니다. 게임 화면을 다시 클릭하면 탐색을 재개합니다. Alt+Tab 등으로 창 포커스를 잃어도 입력이 중단되며, 돌아온 뒤 다시 클릭해야 합니다.
- 대시보드에서는 이동·시선·3D 상호작용이 멈추고 마우스 커서로 UI를 조작합니다. 상단 **사령부로 돌아가기 · Esc** 버튼이나 **Esc**로 닫으면 이전 위치와 시선에서 탐색을 재개합니다.
- **모의 매매계획** 팝업이 열려 있으면 첫 **Esc**는 팝업만 닫습니다. 다음 **Esc**가 대시보드를 닫습니다. 탐색으로 돌아온 뒤 다시 **Esc**를 누르면 마우스가 해제됩니다.
- 대시보드는 최초 열기 시 한 번 생성해 재사용합니다. 닫았다 열어도 이번 실행의 종목 선택과 목표 비중은 유지됩니다.
- 관심종목을 선택하거나 종목명·6자리 코드로 검색합니다. 1개월·3개월·1년 차트, OHLC 표시와 20일 평균선을 확인할 수 있습니다.
- 목표 비중을 조절하고 **모의 매매계획 보기**를 누릅니다. 목표 비중 합계가 100%를 넘으면 계획 버튼이 비활성화됩니다. **목표 비중 초기화**로 되돌립니다.
- 1280×720과 1440×960에서 사용할 수 있습니다. 내용이 화면보다 길면 대시보드 안에서 세로로 스크롤합니다. 닫기 버튼은 위에 고정되어 있습니다.

## 검증

프로젝트 폴더에서 실제 Windows Godot으로 기존 데이터·UI 테스트와 새 사령부 통합 테스트를 실행합니다.

```powershell
$godot = 'C:\Users\hanso\Tools\Godot\Godot_v4.7.2-stable_win64.exe'
& $godot --headless --path . --script res://tests/smoke_test.gd
& $godot --headless --path . --script res://tests/camp_smoke_test.gd
& $godot --headless --path . --script res://tests/camp_visual_test.gd
& $godot --headless --path . --script res://tests/first_person_test.gd
& $godot --headless --path . --quit-after 60
```

성공 시 테스트는 각각 `PHALANX_SMOKE_TEST: PASS`, `PHALANX_CAMP_SMOKE_TEST: PASS`, `PHALANX_CAMP_VISUAL_TEST: PASS`, `PHALANX_FIRST_PERSON_TEST: PASS`를 출력하고 종료 코드 0을 반환합니다. 통합 테스트는 설정된 메인 씬 로딩, 초기 탐색 클릭, 중앙 조준·E 열기, 닫기 버튼·단계별 Esc, 뒤쪽 클릭 차단, 인스턴스·신호 중복 방지, 두 창 크기에서 조작부의 스크롤 접근성을 확인합니다.

시각 구조 테스트는 천막 메시·법선, 외부 텍스처가 필요 없는 재질, 야영지 구성, 초기 눈높이와 두 창 크기의 조준점·안내 배치를 검사합니다. 1인칭 테스트는 합성 키보드·마우스·포커스 이벤트와 실제 물리 프레임으로 이동 속도·시선 제한·충돌·통로·탐색 경계·거리·가림·대시보드 입력 정지를 검사합니다. 비대화형 검사이므로 운영체제의 실제 포커스 전환이나 마우스 캡처, 셰이더의 색감·음영·화질에 대한 직접 검토를 대신하지 않습니다.

비대화형 검증만으로 실제 렌더링 품질이나 물리 마우스 조작까지 확인할 수는 없습니다. Godot에서 다음 항목도 확인합니다.

1. F5 실행 후 안내에 따라 클릭하고 WASD·마우스로 천막 내부와 입구 주변을 둘러봅니다. 천막·테이블·기둥·큰 상자·탐색 경계를 통과하거나 바닥 아래로 떨어지지 않는지, 테이블 옆 통로로 입구에 나갈 수 있는지 확인합니다.
2. 멀리서 테이블을 바라볼 때 안내가 없고, 가까이에서 중앙 조준점으로 바라볼 때만 강조·E 안내가 나타나는지 확인합니다. 벽이나 물체가 사이에 있으면 선택되지 않아야 합니다.
3. E로 대시보드를 열고 검색·차트 기간·목표 비중·모의 계획을 조작합니다. 열린 동안 WASD·마우스가 3D 위치와 시선을 바꾸지 않는지 확인하고, 가상 데이터 표시도 확인합니다.
4. 모의 계획 팝업에서 첫 Esc로 팝업만 닫고 다음 Esc로 사령부에 돌아오는지 확인합니다. 닫기 버튼과 Esc로 여러 번 열고 닫아 위치·시선·설정 비중이 유지되고 UI가 겹치지 않는지 확인합니다.
5. 탐색 중 Esc로 마우스를 해제하고 다시 클릭합니다. 이동키를 누른 채 Alt+Tab으로 전환했다가 돌아온 뒤, 클릭하기 전에는 움직이지 않고 클릭 후에는 새 키 입력 전까지 정지하며 첫 마우스 이동에 시점이 튀지 않는지 확인합니다.
6. 창을 1280×720과 1440×960으로 바꾸어 조준점·안내·닫기 버튼이 보이고 스크롤로 주요 대시보드 조작부에 접근할 수 있는지 확인합니다. 이동 중 천막과 재질이 깨지거나 너무 어두운 곳이 없는지도 살펴봅니다.

인증서 저장소 등 환경 관련 메시지가 나오더라도 검증을 위해 보안 설정을 변경하지 않습니다. 테스트는 별도 프로세스로 실행하며 열린 에디터를 종료할 필요가 없습니다.

## 구조와 후속 작업

- `scenes/command_camp.tscn`, `scripts/command_camp.gd`: 시작 씬과 사령부 구성요소 연결
- `scripts/camp_environment.gd`: 공간 구성요소 연결, 기존 보급품·군기·테이블 강조
- `scripts/camp_architecture.gd`: 두께 있는 붉은 천장·안감·묶은 커튼, 판재 플랫폼·경사로·직조 카펫
- `scripts/camp_table.gd`: 모서리·받침을 갖춘 테이블, 굽은 종이·해안선·입체 지형·행군 경로·군단 표식
- `scripts/camp_lighting.gd`: 석양·하늘·주변광과 청동 화로·숯·입체 불꽃·빛 변화
- `scripts/camp_player.gd`: 1인칭 이동·시선, 마우스 캡처·해제, 포커스·입력 상태
- `scripts/camp_collision.gd`: 바닥·천막·소품·탐색 경계의 충돌 형태
- `scripts/camp_materials.gd`, `shaders/camp_*.gdshader`: 목재·천·청동·양피지·흙의 절차적 재질 생성
- `scripts/camp_backdrop.gd`: 가까운 천막 8개·군기 5개, 중거리 천막 36개, 강·수목·3단 산맥
- `scripts/table_interaction.gd`: 중앙 시선의 거리·가림 판정과 E 상호작용
- `scripts/dashboard_overlay.gd`: 대시보드 지연 생성·재사용, 닫기·Esc, 입력 차단
- `scenes/headquarters.tscn`, `scripts/headquarters.gd`: 기존 2D 대시보드와 반응형 배치
- `scripts/price_chart.gd`: 일봉·거래량·20일 평균선과 OHLC 확인
- `scripts/demo_data.gd`: 가상 데이터, 자산·매매계획 계산
- `tests/smoke_test.gd`, `tests/camp_smoke_test.gd`: 기존 기능과 사령부 통합 검증
- `tests/camp_visual_test.gd`: 천막·재질·야영지 구조, 초기 눈높이와 두 창 크기의 HUD 배치 검증
- `tests/first_person_test.gd`: 이동·충돌·거리·가림·시선 제한·포커스·모달 입력 정지 검증

가상 계좌의 평가자산은 100,000,000원이며 보유종목 평가액 69,070,000원과 현금 30,930,000원의 합입니다. 목표 수량은 `floor(평가자산 × 목표 비중 / 가격)`으로 계산합니다. 매도 대금을 즉시 사용할 수 있다고 가정하며 수수료·세금·결제 시차·체결 오차는 반영하지 않습니다.

후속 단계에서 기존 Python 엔진의 분석 결과 형식을 확인하고 읽기 전용 데이터 어댑터를 연결할 계획입니다. 현재 탐색 범위는 지휘 천막 내부와 가까운 야영지로 한정하며 먼 천막과 지형은 배경입니다. 캐릭터 모델·점프·달리기·NPC·음성·Python 연결·실제 주문 기능은 없습니다.

## 패스 A — 공간·지도·빛

사용자 제공 두 시안의 넓은 붉은 군막과 가까운 지도 테이블을 기준으로 형태를 다시 구성했습니다. 외부 이미지·모델·패키지를 도입하지 않고 프로젝트의 절차적 메시와 재질로 제작했습니다. 참모 제작(패스 B)과 분석 화면 미술 변경(패스 C)은 포함하지 않습니다. 기존 1인칭 입력과 대시보드는 유지합니다.

상판은 1.35m에서 1.02m로 낮췄으며, 눈높이 1.65m를 유지하고 시작 위치를 테이블 중심에서 2.65m, 아래 시선 15도로 조정했습니다. 폭 8.6m의 군막 안에서 최고 천장은 3.95m이며, 판재 바닥과 외부 지면 사이 14cm 차이는 입구 전체 폭의 경사로로 연결합니다. 테이블 둘레와 양쪽 통로를 걸을 수 있습니다.

씬의 `ReviewCamera`는 구도 검수용 고정 카메라입니다. 기본 실행에서는 비활성이며 플레이어 카메라를 바꾸지 않습니다. 같은 구도·해상도로 입구, 테이블 앞·뒤·좌·우와 대시보드를 캡처하려면 다음 선택 검증을 사용할 수 있습니다. PNG와 로그는 프로젝트 밖 임시 폴더에 저장합니다.

```powershell
$review = Join-Path $env:TEMP 'phalanx-pass-a-review'
New-Item -ItemType Directory -Force -Path $review | Out-Null
& $godot --path . --script res://tests/camp_art_review.gd --log-file (Join-Path $review 'review.log') -- $review review
```

이 검증은 실제 GPU를 사용하므로 `--headless`를 붙이지 않습니다. 동일한 여섯 시점과 대시보드를 1280×720/1440×960으로 저장하고, VSync를 끈 검수 프로세스의 프레임 간격과 합성 E 이벤트부터 그려진 프레임까지의 시간을 기록합니다. 물리 키보드·마우스 지연이나 순수 GPU 시간 측정은 아닙니다. 두 버전을 비교할 때 같은 검수 스크립트를 각각의 프로젝트 경로에서 순서대로 실행합니다.

현재 결과는 입체적인 프로토타입입니다. 시안의 사실적인 조각·직물의 불규칙한 큰 주름·암석/식생 밀도에는 미치지 못하며, 화염은 단순화한 입체 셰이더이고 연기 시뮬레이션은 없습니다. 지도 지형도 가독성을 위한 양식화된 표현이며 역사적 지리 복원이 아닙니다. 자동 테스트와 렌더 확인을 이러한 미술적 한계의 해소로 취급하지 않습니다.
