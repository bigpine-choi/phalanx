첫 실행은 WSL 저장 목록을 읽는다. 검색 입력은 로컬 목록만 조회한다. 공개 종목 마스터의 네트워크 수집은 **목록 갱신**에서 명시적으로 실행한다. 목록이 없거나 검색 결과가 0개이거나 갱신에 실패한 상태를 구분한다. 실패 시 마지막 정상 목록과 수집 시각을 유지한다.

검색 범위에는 ETF·ETN·우선주와 기타 마스터 항목도 포함된다. 식별자 충돌은 행을 유지하면서 등록을 막는다. 기존 워크스페이스 및 일봉 경로의 6자리 대문자·숫자 코드에 맞지 않는 항목은 사유를 표시한다. 코드 형식이 지원되어도 실제 일봉 제공 여부는 조회 결과에 따른다. 미보유 종목의 배분 시뮬레이터 편입은 후속 범위다. 종목 선택은 유료 AI 요청을 실행하지 않는다.

## 마무리 검토의 수정·재검증

- 브리지: 미확인 우선주 분류를 보통주로 단정하던 표시와 종목명 80자 저장 한도 판정을 수정했다. Python 계약 테스트 5개와 컴파일 검사 통과.
- 최신 4,405개 discovery SQLite의 격리 사본에 오프라인 수집기를 주입하여 부분 성공·실패를 재현했다. 두 경우 모두 `REFRESH_FAILED`, 4,405개 이전 정상 목록과 정확한 시각 보존을 확인했다. 운영 SQLite의 크기·수정 시각은 변하지 않았다.
- 비동기 모델: 초기 목록 읽기 중 요청한 갱신은 한 번 이어 실행하고, 이미 갱신 중인 중복 요청은 합친다. 응답 식별자·형식 검증을 강화하고 명시적인 갱신 실패에만 이전 Python 스냅샷을 복원한다. 캐시 임시 파일은 같은 프로세스 안에서도 고유하게 만들고 실패 시 정리한다.
- 최초 정상 자료 없이 부분/실패 시도만 있는 경우에도 최근 목록 갱신 실패를 구체적으로 표시한다. 수정한 모델·연결 계약은 31개 검사 통과.
- 연결부 수정 후 실제 Godot → WSL 저장 목록 읽기 검사를 한 번 추가 실행하여 통과했다. 4,405개, 위 최신 수집 시각과 일치하며 네트워크 수집은 실행하지 않았다. `우선주` 검색 결과에는 미확인 분류나 이름 일치도 포함되므로 검색 건수와 확정 종류별 건수는 구분한다.
- 화면·저장 경계: 리서치 진입 시 상단의 종목·차트를 먼저 보여주도록 스크롤을 수정했다. 이전 검색의 충돌 문구를 초기화하고 관심 1,000개 저장 한도를 추가 전에 검사한다. 미지원 일봉 사유의 상태색도 맞췄다.
- 늦게 도착한 계좌 응답의 코드가 같고 종목명이 다른 경우 기존 검색·저장 이름을 덮어쓰던 경로를 막았다. 재실행에서 복원한 이름도 보호한다. 충돌 종목의 보유 포지션·일봉·참모 계획 연결과 참모 요청을 보류하고 사유를 표시한다. 실제 계좌 원본이나 포트폴리오 원본은 바꾸지 않는다.
- 최종 관련 회귀: 검색 UI **39**, market_live **33**, advisor **73**, workspace_persistence **45**, research_data **61** 검사 통과. 합성 계좌로 늦은 충돌 응답·디스크 이름 보존·재로드 후 충돌·다음 정상 응답의 연결 복원까지 확인했다. 저장 스키마는 변경하지 않았다. 변경하지 않은 명령서·야영지 등 나머지 묶음은 앞선 통과 결과를 유지하고 반복 실행하지 않았다.

## 실제 창 조작

컴퓨터 사용 도구로 운영체제 키보드·마우스를 조작했다. 사람이 직접 수행한 검증이나 합성 Godot 입력과 구분한다.

- 앞선 구현 단계: 1280×720과 1440×960 별도 Godot 창에서 검색·등록·노트·재실행 복원·스크롤·버튼 가독성을 확인했다.
- 마무리: 격리 환경을 상속한 새 편집기에서 실제 F5를 눌러 기본 `scenes/phalanx.tscn`으로 시작했다. 1440×960 야영지에서 입구로 이동하고 사령부·시장 전체 검색에 진입했다.
- 실제 목록 갱신 후 `삼성전자우`를 한글로 검색하여 `005935 / KOSPI / 우선주`와 출처·시각을 확인했다. 미보유 종목을 관심에 추가하고 시장 차트의 실제 KIS 일봉 수신을 확인했다.
- 리서치 제목·일봉·참모 제목이 삼성전자우로 일치했다. AI 버튼은 누르지 않았으며 미보유 종목의 비중 변경은 비활성 상태였다.
- 격리 노트 `F5 최종 검증 · 삼성전자우 관심과 노트 복원`을 입력했다. 저장본의 관심 코드 1개·종목명·노트가 일치했으며 게임 프로세스를 종료했다.
- 같은 격리 프로필을 **새로운 1280×720 독립 프로세스**에서 열었다. 기본 야영지 → 사령부 입장 → 지도 클릭을 각각 확인했다. 코드 `005935` 검색 시 관심 등록됨 버튼이 비활성이며 저장된 이름·관심·정확한 노트 내용이 복원됐다. 일봉 네트워크를 끈 상태에서도 해당 코드의 저장된 차트와 리서치·참모 대상이 일치했다.
- 수정 후 종목 분석·참모 진입 시 상단의 제목과 차트가 즉시 보이며, 아래로 스크롤하면 노트를 읽고 편집할 수 있었다. 목록은 네트워크 수집 없이 WSL에서 다시 읽어 같은 4,405개·시각 및 미확인 분류 13개를 확인했다. 독립 프로세스 런타임 로그에 오류가 없었다.

## 직접 확인 순서와 한계

1. 별도 임시 폴더를 만들고 `PHALANX_WORKSPACE_PATH`, `PHALANX_CATALOG_CACHE`, `PHALANX_RESEARCH_CACHE`를 그 안으로 지정한 환경에서 편집기를 시작한다. `PHALANX_ACCOUNT_OFFLINE=1`로 실제 계좌를 조회하지 않을 수 있다.
2. F5 → 야영지 입구 → 사령부 지도 → 시장 전체 검색. 저장 목록이 보이는지 확인하고 한글 이름·종목코드로 검색한다.
3. 미보유 종목의 코드·시장·종류·출처·시각을 확인한 뒤 관심 추가. 시장 일봉, 리서치, 참모 제목이 동일 종목인지 확인한다.
4. 노트를 입력하고 종료한 다음 같은 임시 저장 경로로 다시 실행한다. 관심 목록·이름·노트가 복원되고 중복 추가가 비활성인지 확인한다.
5. 무자료·갱신 실패·충돌은 운영 데이터 변경 없이 아래 격리 테스트로 확인한다. 실제 수집을 원할 때만 목록 갱신을 누른다.

실제 전체 종목 각각의 일봉 제공 여부, 다른 PC의 WSL 배포, OpenDART와 유료 AI 요청은 이번 검증에 포함하지 않는다. 검색 범위는 기존 KOSPI/KOSDAQ discovery 마스터가 제공하는 항목이며 해외·모든 금융상품 전체를 뜻하지 않는다. 이번 커밋에는 인증정보·사용자 프로필·실제 계좌 자료·공개 목록/일봉 캐시·검증용 임시 저장본을 포함하지 않는다.
