## 자동 검증

실제 Windows 실행 파일로 다음 네 테스트가 모두 PASS, 종료 코드 0이었다.

- `smoke_test.gd`: 기존 데이터·계산·대시보드.
- `camp_smoke_test.gd`: E 열기·닫기·단계별 Esc·모달 입력 차단·인스턴스/신호 재사용·두 해상도 UI 접근.
- `camp_visual_test.gd`: 천막 법선·뒷면, 지도 종이 앞뒤·굽음, 상판/충돌 높이, 비활성 검수 카메라와 플레이어 시점·HUD.
- `first_person_test.gd`: 합성 입력을 통한 이동·시선 제한·거리·가림·포커스·충돌, 외부 지면과 경사로 왕복. 커튼 치맛단과 기둥은 별도 높이에서 검사한다.

추가 GPU 이동 검수는 합성 WASD를 실제 물리 프레임에 유지해 앞→오른쪽 통로→테이블 뒤→왼쪽 통로→앞으로 순환하고 E 열기·Esc 복귀까지 통과했다. 이것은 실제 사람이 키를 길게 누른 검증과 구분한다.

## 실제 창과 렌더 확인

Windows 실제 창에서 클릭 탐색 시작·테이블 강조·E 열기·스크롤·모의 계획 팝업·첫 Esc로 팝업만 닫기·다음 Esc로 복귀·재열기·닫기 버튼을 확인했다. 1280×720과 1440×960에서 화면과 조작부를 확인했다. 에디터로 포커스를 옮겼다가 돌아오면 클릭 대기 상태가 되었다. 기존 에디터는 종료하지 않았고 별도 검수 창만 정상 종료했다.

동일한 여섯 카메라 위치/방향과 두 해상도로 변경 전후 실제 D3D12 이미지를 비교하고, 별도로 최종 시작 시점과 이동 경로를 렌더링했다. 지도 앞판 비중, 종이 가장자리, 천막 뒤쪽 틈, 화로 그릇의 뒤집힌 면을 발견해 수정했다. 최종 이미지에서 지도·천막의 앞뒤·양옆, 플랫폼 접지와 빛 경계가 보이는 것을 직접 확인했다. 고정 비교에서는 화로 광량 변화를 멈췄으며 셰이더 불꽃/깃발의 미세한 위상은 다를 수 있다.

물리 키의 지속 WASD, 실제 상대 마우스 회전, 이동키를 누른 채 Alt+Tab은 직접 검증 완료로 기록하지 않는다. 사용자는 F5 → 클릭 → 테이블 한 바퀴/입구 경사로 왕복 → E → 팝업 Esc 두 번 → 이동키를 누른 채 Alt+Tab 순서로 확인할 수 있다.

## 같은 PC에서 측정한 비용

RTX 5070 Ti Laptop GPU, D3D12 Forward+, MSAA 4×/TAA, 검수 프로세스 VSync 해제. 작업 시작의 미커밋 사본과 최종 소스를 순서대로 실행했다. 고정 구도의 메인 루프 프레임 간격 600개와 합성 E→렌더 완료 이벤트 8개를 측정했다.

| 해상도 | 프레임 간격 중앙값, 전→후 | 프레임 간격 p95, 전→후 | 합성 E 반응 중앙값, 전→후 |
| --- | --- | --- | --- |
| 1280×720 | 1.939 → 2.648ms | 2.860 → 3.647ms | 18.183 → 20.688ms |
| 1440×960 | 1.327 → 2.396ms | 2.152 → 3.182ms | 17.387 → 17.006ms |

장면 비용은 증가했다. 이 수치는 짧은 단일 실행의 메인 루프 간격이며 순수 GPU 시간·실제 표시 지연·물리 입력 지연·지속 FPS를 뜻하지 않는다. E 표본에는 최초 지연 생성이 포함되며 1280×720의 최댓값은 전 84.630ms/후 77.257ms였다. 해상도별 실행 순서·캐시·GPU 클럭 영향도 있으므로 작은 반응 시간 차이를 개선으로 판단하지 않는다.

검수 스크립트는 `tests/camp_art_review.gd`, 로그·PNG·비교 전 소스 사본은 `%TEMP%\phalanx-pass-a-review`에 있다. `before-final-*`, `after-final-*`는 같은 고정 구도이며 `tour-*`는 최종 플레이어 이동/시작 화면이다. 이 산출물은 프로젝트와 Git 스테이징에 넣지 않았다.

샌드박스 실행에는 기존 인증서 저장소 읽기 오류와 일부 셰이더 캐시 저장 오류가 기록됐다. 최종 스크립트/셰이더 파싱 오류는 없었고 실제 사용자 데스크톱 GUI 로그에도 이 오류는 없었다. 보안 설정은 바꾸지 않았다.

## 남은 미술 한계
