# Phalanx · 실계좌와 작전 시뮬레이터

사령부의 지도 → **Ⅱ 포트폴리오**에서 사용합니다.

## 실제 계좌 조회

기존 한국투자증권 Python 서비스와 WSL의 계좌 설정을 연결했습니다. 처음 포트폴리오 탭을 열면 계좌와 보유종목 가격을 조회합니다. 이후 **계좌 새로고침**으로 갱신합니다.

- 증권사 순자산, 예수금, 주식평가액, 평가손익
- 보유종목 전체의 수량, 조회가, 조회가 기준 평가액, 증권사 평가손익
- 계좌번호 마스킹, 조회 시각, 종목 수
- 조회 실패 시 이전 잔고 표시와 새 계획 계산 차단

조회가는 조회 시점의 가격입니다. 실시간 스트리밍이나 확정 체결가격이 아닙니다. 종목별 조회가 평가액과 증권사 계좌 요약은 서로 다른 관측 시점·평가 기준일 수 있습니다.

## 변경안 만들기

1. **시뮬레이션 투입 현금**에 계획에서 사용할 현금 가정값을 입력합니다. 기본값은 0원입니다.
2. 각 종목 오른쪽의 목표 비중을 바꿉니다. **현재 비중**은 현재 보유량을 유지하는 출발점, **동일 비중**은 보유종목 간 균등 배분 예시입니다. 비중 합계의 나머지는 계획 현금입니다.
3. **변경안 계산**을 누릅니다. 종목별 현재→계획 비중, 매수·매도 수량·금액, 변경 후 현금과 최대 단일종목 비중을 확인합니다.
4. 필요하면 **참모 검토 · 종목/비중 전송**을 누릅니다. 종목명·코드·비중 변화와 가정 설명만 OpenAI로 보내며 금액·수량·계좌번호는 보내지 않습니다. API 사용료가 발생할 수 있습니다.
5. **명령서에 적용**을 누릅니다. 계산 근거가 초안에 붙고, 작전 이름과 위험을 작성해 **명령서 봉인 · 기록**을 누르면 사령부의 작전 일지에서 다시 볼 수 있습니다.

**작성 중 명령서**로 저장된 실계좌 기반 초안을 다시 엽니다. 샘플 계좌의 목표·초안·기록은 별도로 유지됩니다.

## 계산 범위

- 분모: 조회가 기준 보유주식 가치 + 사용자가 입력한 현금 가정.
- 증권사 순자산 전체나 주문가능금액을 뜻하지 않습니다. 기존 계좌 API가 주문가능현금을 제공하지 않으므로 예수금을 자동 대입하지 않습니다.
- 현재 보유종목에 대한 1주 단위 재배치입니다. 신규 종목 추가, 공매도, 레버리지는 지원하지 않습니다.
- 비중 변경은 기존 Python의 `apply_fractional_self_financing_transition`을 호출한 뒤 1주 단위로 내림하고 남는 현금을 대사합니다. 현재 보유량 유지는 매매 없는 정확 계산이며, 현금 100% 시나리오는 별도 전량 매도 계산입니다.
- 목표 비중 100% 초과, 비정상 수치, 매도가능수량 초과는 막습니다. ‘현재 비중’은 표시용 비중 반올림 때문에 불필요한 매매가 생기지 않게 보유량을 유지합니다.
- 수수료·세금·호가 차이·결제 지연은 제외합니다. 매도 대금 재사용은 시뮬레이션 가정입니다.
- 위험 비교는 현금과 단일종목 집중도입니다. 기대수익률·변동성·상관관계·ETF 구성종목은 계산하지 않습니다.
- 실제 주문을 전송하는 기능은 없습니다.

## 저장과 Python 연결

계좌 원본 관측은 기존 Python 서비스가 WSL의 개인 데이터 폴더에 저장합니다. 게임에는 표시·계산에 필요한 허용 필드만 전달합니다. 조회한 잔고는 게임 메모리에 유지하며, 명령서에 적용한 계획과 봉인한 기록은 기존 Godot 개인 저장 파일에 보관합니다. API 키·KIS 인증정보는 명령서와 요청 인자에 넣지 않습니다.

프로젝트 코드: `account_bridge.py`(기존 계좌 서비스), `portfolio_engine.py`(배분 계산), `portfolio_bridge.py`(계산/참모), `portfolio_process.gd`(프로세스 연결), `portfolio_simulator.gd`(게임 화면).

기존 위험 기반 자동 비중 산출기는 전체 종목의 공통 관측 이력이 필요하므로 이번 수동 변경안 계산에 억지로 연결하지 않았습니다. 이번에는 단일 조회 시점에 맞는 기존 자산·현금 배분 함수를 연결했습니다.

## 확인한 사항

실제 KIS 계좌 서비스에서 11개 보유종목을 조회했습니다. 해당 관측 자료를 외부로 보내지 않고 현재 보유 유지·균등 비중·단일종목·전량 현금·가정 현금을 포함한 보유 유지의 다섯 시나리오를 계산했습니다.

Python 테스트 12개와 Godot 통합 검사 41개가 통과했습니다. 수량 내림·현금 대사·과배분·매도제한·긴 소수 비중·조회 취소 시 임시 잔고 정리·AI 전송 정보 최소화, 계산 무효화·참모 오류 시 계산 보존·명령서 저장/재열기·샘플 계좌 분리·네 창 크기를 검증했습니다. 기존 참모·명령서·저장·워크스페이스 검사도 통과했습니다.

포트폴리오 AI 검토는 합성 데이터로 실제 OpenAI 응답을 확인했습니다. 이번 검증에서 사용자의 실제 보유종목을 OpenAI로 보내거나 실제 계좌 기반 명령서를 임의로 봉인하지 않았습니다.
