질감 이미지는 천의 처짐이나 테이블 조각 형태를 대신하지 못한다. 큰 형태를 먼저 고친 뒤 재질을 적용한다. 모든 표면에 같은 노이즈나 갈색 필터를 적용하지 않는다.

## 4. 첫 제작 범위

첫 범위는 테이블을 한 바퀴 돌 수 있는 지휘 천막 하나와 짧은 입구 공간이다. 전체 야영지, 다섯 NPC, 군마까지 동시에 완성하려 하지 않는다.

### 패스 A — 공간·지도·빛

1. 현재 시작 시점의 눈높이, 테이블 높이, 플레이어와 테이블 사이 거리, 시선 각도를 함께 점검한다. 화면만 보고 원인을 한 변수로 단정하지 않는다.
2. 붉은 천장/군기와 베이지색 안감, 묶은 입구 커튼, 목재 플랫폼과 카펫으로 큰 공간 구조를 만든다.
3. 테이블 형태와 작전 지도를 새 기준으로 개선한다. 가까운 면의 두께·가장자리·뒷면을 실제 메시로 처리한다.
4. 동일한 시간대의 석양·화로·주변광을 맞춘다. 어두운 부분을 무조건 밝히거나 과도한 안개·블룸으로 결함을 가리지 않는다.
5. 근경/중경/원경의 배치를 잡고 화면을 실제로 비교한다. 이 패스의 완료는 참모까지 포함한 전체 시안 재현 완료를 뜻하지 않는다.

### 패스 B — 핵심 소품과 첫 참모

- 투구, 방패·창, 두루마리, 책, 청동 그릇을 제한된 묶음으로 배치한다. 모든 빈 공간을 소품으로 채우지 않는다.
- 참모는 먼저 한 명을 완성한다. 외형·의상·리깅·대기 동작을 검증하고 이후 다섯 참모로 확장한다.
- 참모의 존재감은 실제 3D 외형과 동작으로 만들고, 모델 확보가 안 되면 미완성으로 보고한다. 평면 인물 컷아웃을 최종 3D 구현으로 보고하지 않는다.

### 패스 C — 분석 화면의 미술 통일

- 첫 참조 아래쪽의 차트/표/참모 의견 구조를 기존 데이터와 기능에 맞춰 적용한다.
- 기본 화면은 짙은 회색, 텍스트는 밝은 중성색, 강조는 청동색, 성과선은 청록색을 중심으로 잡는다.
- 차트·수치·텍스트는 실제 UI로 렌더링한다. 시안 속 예시 기업·비중·성과를 실제 계산값으로 사용하지 않는다.
- 분석할 때는 배경 움직임과 밝기를 조절하고, 입력은 기존대로 대시보드가 받는다. 투자 기능에 매번 보행을 강제하는 구조로 확대하지 않는다.

## 6. 시각적 완료 기준

같은 해상도와 조명 상태에서 입구, 테이블 정면, 왼쪽, 오른쪽, 테이블 뒤, 분석 패널을 비교한다. 실제 자유 이동 중 모습도 확인한다.

- 천막 폭과 천장 높이가 인물·테이블에 비례하고 테이블 순환 동선이 확보된다.
- 처음 시작하면 지도와 입구 방향이 자연스럽게 읽힌다. 테이블 앞판·다리가 화면의 중심이 되지 않는다.
- 진홍색 직물, 짙은 목재, 청동, 양피지의 차이가 가까이서도 드러난다.
- 큰 천 주름, 테이블 외곽, 지도와 소품은 다른 각도에서도 입체가 유지된다.
- 배경에 근경·중경·원경이 존재하며 접근 불가능한 배경과 이동 영역이 자연스럽게 연결된다.
- 오브젝트 뒷면, 조명 경계, 접촉 그림자, 바닥 접지, 재질 반복과 확대 흐림을 확인한다.
- 대시보드·E·Esc·포커스·충돌의 기존 계약을 보존한다. 관련 변경이 생긴 항목만 재검증한다.
- 같은 PC/해상도에서 변경 전후 프레임 시간과 입력 반응을 비교한다. 측정하지 않은 성능이나 시안 재현율을 제시하지 않는다.
- 자동 테스트 통과, GUI 조작 확인, 미술 품질 평가는 별도로 보고한다. 첫 두 항목의 통과로 미술 완성을 선언하지 않는다.

## 7. VS Code Codex에 전달할 지시

이 문서와 원본 이미지 두 장을 함께 제공한다. 다음 지시를 사용한다.

> 두 첨부 이미지를 Phalanx 사령부의 시각적 기준으로 삼아 이 문서의 패스 A를 구현해줘. 두 번째 이미지의 넓은 공간 구성과 첫 번째 이미지의 가까운 재질·조명을 결합하되, 기존 1인칭 이동과 대시보드 기능을 유지해줘. 먼저 현재 지침·Git 상태·소스 구조와 필요한 제작 도구의 설치 상태를 확인해줘. 최근 1인칭 미커밋 변경을 보존하고, 커밋·병합·푸시·강제 초기화는 하지 마. 창작·모델링이 필요한 부분을 재질만 바꾼 것으로 완료 처리하지 마. 공식 출처와 상업 사용 조건을 확인한 무료 재질은 프로젝트 범위에서 도입할 수 있지만 유료 구매·계정 생성·새 프로그램 설치는 별도 결정을 받아야 해. 외부 리소스에 접근하지 못하면 막힌 항목을 구체적으로 보고하고 가능한 작업은 진행해줘. 코드 책임을 공간·재질·입력·UI로 나누고 같은 파일에 모든 기능을 몰아넣지 마. 같은 구도와 여러 이동 시점에서 실제 실행 화면을 비교하고, 아직 부족한 모델/재질/연출을 명시해줘. 다음 패스까지 임의로 확대하지 말고 패스 A의 구현과 가능한 검증을 끝내줘.

이 작업 지침은 첫 미술 제작 단위를 정의한다. 두 시안과 동일한 완성 화면을 한 번의 코드 생성으로 보장하지 않는다. 첫 결과에서 가장 큰 차이를 다시 골라 다음 모델과 재질에 작업 시간을 배분한다.
