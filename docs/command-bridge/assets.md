## 자산 목록과 제작 경로

P0는 **임시 선택한 엔진 하나의 사실적 고품질 3D 연결 실험**에 필요한 항목, P1은 대표 함교 부하 검증과 첫 장면 전체,
P2는 장기 여러 공간·다섯 참모·추가 미니게임으로 확장할 항목이다. P2는 이번 제작 착수가 아니다.
P0에서도 승인했던 사실적 함교의 인물·환경 품질을 실제로 평가할 수 있어야 한다.
기본·고급 설정에 필요한 자산 변형과 검수를 포함하고, 기본의 캐릭터/상호작용 매력을 유지한다. 임시 도형과 기본 인체는

## 제작 인계와 자산 기록 형식

각 자산은 다음 필드를 채운 뒤 승인한다. 문서의 후보 목록을 이미 확보된 manifest로 사용하지 않는다.

```text
asset_id / 담당 역할 / P0·P1·P2 / 상태(후보·취득·권리확인·수입·품질승인)
원본 URL / 제작자 / 취득일 / 버전 / 실제 파일명과 SHA-256
license 식별자·원문 사본 / 영수증 또는 의뢰 계약 / 사용·수정·제품 배포·원본 재배포 범위
외부 원천 목록 / attribution / 모델·이미지의 인물/상표 권리
DCC·exporter·엔진 버전 / 단위·축·원점 / skeleton 이름·bind pose·root motion 규칙
mesh·LOD·material slot·bone 수 / texture 해상도·format·색공간 / animation 목록·길이
공용/공간별 소유 / load·unload 의존성 / 기본·고급 설정별 변형 / CPU·GPU peak·상주 메모리
수입 설정 / source와 cooked output 위치 / 검수 장면·영상·오디오 / 승인자·미해결 결함
```

source art와 runtime 산출물을 구분하고 엔진 생성 캐시를 source처럼 다루지 않는다. 선택한
엔진의 단위·좌표축·skeleton·bind pose·exporter를 고정하며 기준 인물/좌석 한 세트로
수입/착석/기립을 먼저 검증한다. Unity는 [Humanoid retargeting](https://docs.unity3d.com/6000.0/Documentation/Manual/Retargeting.html),
Godot는 [수입 포맷](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html),
Unreal은 [FBX 파이프라인](https://dev.epicgames.com/documentation/unreal-engine/fbx-content-pipeline)을
근거로 실제 선택 버전의 호환을 확인한다. 여러 엔진용 runtime 파일을 동시에 제작하지 않는다.

각 공간의 manifest는 asset ID·권리·의존성·상주 예산을 갖는다. 공용 인물 rig/폰트/재질은
참조 횟수로 수명을 관리하고 공간을 나갈 때 중복 timer·구독·audio·GPU 자원을 남기지 않는다.
분석 결과와 놀이 checkpoint에는 mesh/scene 객체 참조를 넣지 않는다. 장소의 수가 늘어도
전체 자산을 시작 시 모두 로드하지 않는다. 기본·고급에서 선택할 사물/인물/놀이 규칙과
표정·주목·반응은 같다. 설정 전환 중의 자산 중복 메모리와 분석/놀이 상태 보존도 검사한다.

텍스처를 무조건 4K/8K로 올리지 않는다. 고정 카메라에서 차지하는 픽셀·mip·압축·재질 수를
측정하고 [실험의 RAM/VRAM 예산](spec.md#b-성능안정성-합격-제안)에 맞춘다. 인물 머리·의복,
투명 홀로그램과 반사/그림자가 별도 GPU 비용을 만들 수 있으므로 개별 on/off trace를 남긴다.
기술 측정용 debug toggle 결과와 최종 품질 상태의 합격 측정은 구분한다.

## 추가로 필요한 참조 자료

현재 파일이 있다고 가정하지 않는다. 새 요청의 작품은 [역할별 참고표](spec.md#참고-작품의-역할)에
연결하고, 각 sheet에 참고한 원리와 팔랑크스의 고유 변형을 기록한다. 캡처/음원의 연구상 참조와
제품 배포권을 구분한다. 승인 이미지의 로컬 복사나 타 작품 자산 추출을 요구하지 않는다.

1. **구도/스타일 sheet:** 16:10·16:9 fixed-camera thumbnails 2–3안과 데이터 패널 상태.
   승인했던 사실적 함교 목표의 구도·재질·인물 매력을 제작 기준으로 구체화한다.
   채팅 승인 이미지가 저장소에 있다고 가정하지 않으며 현재 텍스트 설명을 근거로 한다.
2. **인물 sheet:** 헤파이스티온 정면/측면/뒤·앉은 모습·표정·손·제복과 다섯 참모의 장기 silhouette
   조합 초안. 역사적 의복/문양은 맥락을 조사해 변형하고 타 캐릭터/실존 배우 외형을 복제하지 않는다.
   다섯 명 전체 모델을 첫 실험에 요구하지 않는다.
3. **재질/조명 sheet:** 금속·직물·유리·피부/눈/머리 swatch와 청록/호박색 명도 기준.
   기본/고급을 나란히 검토해 사실적 분위기·인물 매력·주목·장치 반응이 모두 유지되는지 판단한다.
4. **움직임/사물 반응 sheet:** seated→stand→walk→sit 접점과 눈/목/손 전이,
   hover/focus→선택→작동→완료의 타이밍. 직접 촬영 또는 권리 있는 모션 참조를 확보한다.
5. **우주/함선 sheet:** 고유 호위함 silhouette, 행성 곡률·광원·표면 자전·상대 항해 경로.
   크기/거리별 시차로 규모감이 읽히는 60초 storyboard를 만든다.
6. **플레이/정보 sheet:** 장치 발견→짧은 선택 놀이→완료 알림→결과→놀이 계속의 화면 흐름,
   긴 한글/정확한 수치 type sample, 초점과 중단/재개 위치. 기존 계산 상태와 놀이 진행을 구분한다.
7. **음향 sheet:** room tone/장치/인물 접촉 cue 승인 샘플, 실제 헤드폰·스피커 청취 기록.
   그림이나 mute 테스트로 청취를 대신하지 않는다.

## 병목과 제작 순서

병목은 **사실적 함교의 통일된 미술과 고유 인물의 매력**, 피부·눈·머리·의복의 정합성,
착석/손/발 접촉 모션, 조명·장치 반응이다. 기본에서도 이 목표가 성립하도록 LOD/재질/효과
변형을 제작·검수한다. 여러 공간/다섯 참모의 공통 rig·모듈·변형 규칙도 필요하다.
사실적 목표를 고가 기법이나 초고해상도 자산만으로 해결한다고 가정하지 않는다.
현재 인력·단가·샘플 견적이 없어 금액/납기를 추정하지 않는다.

역할별 환경·캐릭터/애니메이션·technical art·데이터 UI·음향 작업과 검수를 산정한다.
P0의 대표 환경/테이블/헤파이스티온/모션/창밖/폰트·음향/선택 놀이/알림이 첫 실험의 범위다.
정지 화면 → 접점 동작 → 사물 반응/작은 플레이 순환 → 계산 연결/공간 전환 → 실제 동시 부하
순으로 검토한다. 제품 엔진/지원 사양 확정 전에는 P1의 대표 함교에 필요한 자산/화면상 인물 수와
장치·창밖 동작을 갖추고 실제 Python 분석과 함께 측정한다. P0의 작은 장면만으로 확정하지 않는다.
P1의 나머지 완성 작업과 P2의 추가 참모·공간·놀이 제작은 후속 결정이다.
미술·음향은 [독립 게이트](spec.md#c-미술연출-합격), 게임 감각은 [플레이 게이트](spec.md#d-게임-감각-합격)로 판정한다.
