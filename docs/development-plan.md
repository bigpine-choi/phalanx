# Phalanx 개발 계획

기준일: 2026-10-01. 이 문서는 현재 구현과 다음 작업의 기준이다. 예전 기능별 검증 문서와 `game/docs/SESSION_HANDOFF.md`의 과거 항목은 당시 상태를 기록한다.

## 현재 구조와 완료 범위

| 영역 | 현재 상태 | 기준 위치 |
| --- | --- | --- |
| Python 투자 엔진 | KIS 실계좌·일봉 조회, 종목 discovery, 읽기 전용 분석과 계산 | 저장소 루트의 `src/`, `tests/` |
| Godot 게임 | 시장 검색, 관심그룹 시세판, 차트 탐색, 리서치, 모의 포트폴리오, 저장된 연구 배분, 명시적 AI 참모 요청 | `game/` |
| NH PLUG | `~/.nhplug/.env`를 읽는 WSL 공식 SDK로 KRX 현재가를 별도 조회 | `game/tools/nhplug_quote_bridge.py` |
| 인증과 사용자 데이터 | 키·토큰·계좌 관측·노트는 Git 밖에 둠 | WSL 홈과 Godot `user://` |

기능 브랜치에서 실제 NH 3종목 1회 갱신을 확인했다. 2026-10-01 main 통합본은 격리된 합성 자료로 실제 Windows F5 동선·정렬·차트·노트 재실행 복원을 확인했다. 실제 NH 재호출은 반복하지 않았으며 서비스 장애·장시간 운용은 미검증이다. NH 현재가는 KIS 수정주가 일봉이나 실계좌 평가액을 대체하지 않는다. [통합 검증](../game/docs/WATCHLIST_MAIN_INTEGRATION_VALIDATION.md)

`game/`은 지금 실행할 수 있는 Godot 시제품이다. [UE5 사령부 설계 PR #26](https://github.com/bigpine-choi/phalanx/pull/26)은 별도 Draft이며 UE5 실행·연결·패키징 검증은 아직 끝나지 않았다. 이 통합은 현재 게임을 보존하고 개발 기준을 단일 저장소에 두는 작업이다.

## 통합 상태와 다음 작업 순서

| 작업 | 상태·완료 조건 |
| --- | --- |
| Python main에 game/ 통합 | 기존 main에 완료. Python·Godot 검사 범위 분리 유지 |
| 시세판·차트 및 검증된 추가 변경 반영 | 파일별 통합·로컬 검사 완료. PR의 Quality gate 통과 후 main 반영 |
| 실제 Windows 점검 | 1280×720 F5 동선·정렬·선택·차트·노트 재실행 통과. 실제 NH 장애와 장시간 운용은 남은 범위 |
| 다음: 성능 기준선 기록 | 최초 가져오기 시간, 검색 반응, 종목 전환 후 메모리를 같은 조건에서 측정 |
| 이후: 제품 기능 확장 | 사용자 선택에 따라 미보유 종목의 모의 배분 편입을 기존 실계좌 계산과 분리해 설계·검증 |

`game/docs/.gdignore`는 약 116MB의 과거 검증 자료를 Godot 가져오기 대상에서 제외한다. 자료는 Git에서 계속 읽을 수 있다. 리서치 일봉의 메모리 캐시는 최근 12종목으로 제한하며 종목별 디스크 캐시는 유지한다. 이 변경의 실제 시간·메모리 절감량은 후속 성능 기준선 측정으로 확인한다.

## 여러 AI가 동시에 작업할 때

1. 각 작업은 독립된 브랜치와 작업 복사본에서 진행한다. 다른 작업 복사본의 미커밋 파일을 복사하거나 함께 스테이징하지 않는다.
2. 한 PR에는 한 목적과 검증 결과를 담는다. 문서의 과거 검증 수치를 새 커밋의 통과 결과로 재사용하지 않는다.
3. 병합 직전에 원격 `main`과 열린 PR을 다시 확인한다. 먼저 병합된 변경이 있으면 새 기준으로 충돌을 해소하고 검사한다. 강제 푸시나 무관한 브랜치의 일괄 병합은 하지 않는다.
   별도 이력의 기존 게임 브랜치는 `main`에 직접 PR을 열 수 없으므로, 후속 변경을 검토해 `main`의 `game/` 경로에 적용한다.
4. 현재 제품 상태는 이 계획, [공식 백서](../game/docs/PHALANX_WHITEPAPER.md), 각 PR의 검증 결과 순으로 읽는다. `game/docs/`의 오래된 세션 기록은 역사 자료로 취급한다.
5. 키·토큰·실계좌 자료·사용자 저장본은 커밋하지 않는다. 계좌와 시세는 읽기 전용 경계를 유지하고, 실제 주문 개발은 별도 요구와 검증을 필요로 한다.

## 검증 경계

루트의 Python `ruff`, `mypy`, `pytest`는 투자 엔진을 검사한다. 게임의 GDScript와 도구는 `game/`에서 Godot headless 테스트와 필요한 Python 오프라인 테스트로 검사한다. Godot 문서 폴더는 실행 리소스가 아니며 게임 코드에서 `res://docs`를 읽지 않는다. 환경별 실제 API 확인은 자동 검사와 구분해 기록한다.
