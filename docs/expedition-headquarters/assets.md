## 자산 인계와 미확인 참조

자산 manifest는 `asset_id`, 담당 역할/단계, 상태(후보·취득·권리확인·수입·승인), URL/제작자,
취득일/버전/해시, 사용·수정·제품 배포·원본 재배포 범위와 고지를 기록한다. DCC/exporter/engine
버전·단위/축·bind pose·root motion·LOD/bone/material 수·texture 형식/색공간·모션 목록도 남긴다.
기본/고급 변형과 CPU/GPU 상주/최고 메모리·load/unload 의존성·검수 증거를 연결한다.

추가로 필요한 제작 자료는 다음이다. 승인 시제품 파일은 선택적 참고이며 현재 문서 작업의
선행 조건이 아니다.

1. 진홍 천막·테이블·참모·야영지가 있는 16:10/16:9 구도와 명도 sheet, 현대 금융 패널이 열린 상태.
2. 헤파이스티온 얼굴/손/복식/표정과 다섯 참모의 역할별 실루엣 sheet. 특정 시대 유물 근거와 창작 변형 표시.
3. 직물/목재/청동/가죽/석재/피부 swatch, 석양/노출·기본/고급 비교. 정확한 2.5D 이미지 복원이라고 주장하지 않음.
4. 인간의 지도 지시·착석/기립·문서 전달, 천/불꽃/연기, 말의 대기/교감 동작에 대한 권리 있는 참조.
5. 부케팔로스의 체형/표식/마구 콘셉트와 말 전문 애니메이션 작업 가능 인력, 역사 근거의 확인 목록.
6. 한글 type sample·화면 초점/선택 반응·짧은 cue 청취 샘플과 제작/검수 담당자.

## 대형 원본·게임 프로젝트·빌드 보관

다음은 **후속 구현 때의 권고안**이다. 이번에는 저장소·LFS·ignore 파일·artifact 서비스 등을
만들거나 설정하지 않는다. 사용자 자료를 이동하지 않는다.

| 구분 | 제안 위치/버전 관리 | 포함/제외 원칙 |
|---|---|---|
| Python·계약·설계 | 현재 저장소 | 기존 src/tests/lock과 문서 유지. 대형 구매 자산/사용자 금융 자료를 섞지 않음 |
| UE 게임 프로젝트 | 별도 비공개 게임 저장소를 우선 검토, Windows 로컬 checkout | `.uproject`, authored `Source/Config/Content/Plugins`, 필요한 `Build` 자원. `.uasset/.umap`은 바이너리여도 제작 소스이므로 버전 관리 |
| DCC 원본 | 접근 제한된 버전 보관소/백업, asset ID와 revision으로 연결 | `.blend`/원본 texture/audio·mocap·권리 문서. UE용 파생본과 구분; 손실 시 복구/복원 시험 |

| Windows 배포/증거 | 별도 버전 artifact 저장소 | cooked package·Python onedir·필요 DLL/고지·검증 결과·해시. 코드 저장소나 검토 문서에 큰 ZIP/로그/캡처를 무작정 추가하지 않음 |

소규모 시작은 [Git LFS](https://git-lfs.com/)와 binary 잠금 운영을 검토한다. 다수 아티스트의
동시 편집이 커지면 [Epic의 Perforce workflow](https://dev.epicgames.com/documentation/unreal-engine/using-perforce-as-source-control-for-unreal-engine)와 비교한다.
저장소 선택이 유료 자산의 원본 공개 재배포를 허용하지는 않는다. [UE 디렉터리 구조](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-directory-structure)에
따라 `Build` 전체나 binary-only plugin을 생성 파일로 오인해 제외하지 않는다.

릴리스 manifest에서 Python commit/lock, 게임 commit, UE 정확한 patch/SDK, protocol version,
자산 manifest/LFS revision, 설정·실행 파일 해시를 함께 고정한다. 두 저장소를 분리해도 이
manifest로 재현성을 유지한다. 장기 보관소의 용량·권한·백업 예산은 실제 인력/계약과 함께 정한다.

## 제작상의 병목과 착수 조건

가장 큰 병목은 일관된 사령부 미술과 헤파이스티온의 얼굴/의복/접촉 모션, 천막 투광·청동 반사·
야영지 깊이의 조율이다. 다음 단계의 군마는 별도 해부/리깅/모션/손 접점 제작이 필요하다.
엔진 설치나 기성 자산 보유만으로 품질이 완성되지 않는다. 환경·인물/모션·technical art·UI·
음향 역할을 나누고 샘플 견적/작업시간을 확인한 뒤 비용·납기를 정한다.

먼저 T0에서 자산 없이 실제 Python 계산·표시·정상 종료를 검증한다. 이후 P0 자산을 한 구도에
수입 → 정지 미술 검토 → 움직임/지도 반응 → T0 연결을 사령부에 통합 → Windows 동시 성능·
청취의 순서로 판정한다. P1 군마·P2 AI/여러 공간을 P0에 합치지 않는다.
