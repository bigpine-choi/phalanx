# 팔랑크스 원정군 사령부 제작 사양

상태: **현재 적용하는 설계 · UE5 채택 확정 · 제품 구현 전**. 조사일 2026-09-26, 엔진 채택 결정일 2026-09-27.
설계 기준은 `de77b6b41fde2a82753d70cf78eaef11a28449df`이며 브랜치 `design/command-bridge-spec`에서
기존 설계를 이어간다. [기술·환경·검증 계획](../decisions/expedition-headquarters-rendering.md),
[자산·보관 계획](assets.md)이 이 사양의 동반 문서다.

## 1. 확정 방향과 적용 범위

공식 세계관은 **마케도니아 원정에서 영감을 받은 원정군 사령부**다. 사용자는 알렉산더 대왕의
위치에서 다섯 AI 참모와 분석하고 편성하는 경험을 갖는다. **초고사양 PC를 우선 대상으로 하는
고품질 실시간 3D**가 목표다. 공간·인물·재질·조명·애니메이션·음향·상호작용의 미적 완성도를
높이며 현재 보급형 PC 지원을 위해 미술 목표를 먼저 낮추지 않는다.

최소 5년의 개발 의향은 장기 투자 방향이며 5년 뒤 하드웨어나 보급형 실행을 보장하는 근거가
아니다. 사용할 수 있는 버전을 단계별로 완성한다. 품질 설정·자산 수명·최적화를 처음부터
설계한다. **2026-09-27 사용자 결정으로 게임 클라이언트 엔진은 Unreal Engine 5(UE5) 채택을
확정했다.** 구체적인 엔진 버전, Windows 개발환경, Python 연결 방식, 패키징·성능·최소/권장
지원 사양은 후속 검증 대상이다. 엔진 채택 결정은 설치·빌드·실행 검증 완료를 의미하지 않는다.

SF·우주전함·함교·홀로그램·호위함·행성의 미술 방향은 폐기했다. 이전
[함교 사양](../command-bridge/spec.md), [엔진 검토](../decisions/command-bridge-rendering.md),
[자산 검토](../command-bridge/assets.md)는 이력으로 보존한다. 그 문서의 Unity 우선 제안,
스타일화/사실적 SF 비교, 보급형 우선 조건은 현재 요구가 아니다. Python 분리·작업 보존·원본
저장 계약은 이번 문서군에 통합했다. 과거 SF 문서를 새 사령부의 구현 지시로 사용하지 않는다.

사용자가 승인한 2.5D 시제품의 **분위기와 조작감**을 출발점으로 삼는다. 파일·이미지는 로컬에서
확보하지 않았으며 새로 열람했다고 주장하지 않는다. 아래 텍스트 기준으로 설계를 완료한다.
시제품의 대사·진행 표시가 실제 AI나 Python 분석과 연결됐다는 뜻은 아니다.

## 2. 첫 장면: 열린 진홍색 천막

T0 기술 연결 검증 이후의 사령부 시제품(P0)은 대표 부분 한 곳이다. 고정 또는 매우 제한된 카메라를 설계 출발점으로
삼아 구도와 선택 흐름에 집중한다. 실시간 깊이·광원·인물 관절·접촉 동작을 갖춘다.
정지 배경 위 버튼, 이미지 확대/병진, 기본 인체만으로 3D 생활 동작이나 미술 완성을 주장하지 않는다.

| 계층 | 구도와 제작 기준 | 움직임·상호작용 |
|---|---|---|
| 전경 | 문서·두루마리·군장 일부로 시선 유도, 핵심 조작은 가리지 않음 | 집을 수 있는 것과 배경 소품의 강조를 구분. 종이는 짧게 들리거나 정리되는 고유 반응 |
| 중앙 | 목재·청동 작전 테이블과 **상아색** 지도. 재료로 상아를 사용한다는 뜻은 아님 | 지도 선택 시 손짓/지도 위 말·표식의 작은 변화와 정보 패널. SF 발광 투사 효과 없음 |
| 인물 | 지도 주변 참모, P0는 헤파이스티온 한 명을 우측에 배치 | 사용자→지도→대기 시선, 호흡·체중 이동·손으로 지도 가리키기·짧은 자세 전환 |
| 천막 | 열린 진홍색 직물, 봉제·주름·지지대·장력과 따뜻한 투과광 | 고정점은 유지하고 천막 끝과 군기의 바람 반응을 다르게 설정. 천 전체의 평행 이동 금지 |
| 바깥 중경 | 야영지 일부, 군기·군장·문서 운반 동선 | 후속 확장에서 병사·전령의 정지·출발·보행·전달·휴식. 발 접지·걸음 전이와 경로 예약 필요 |
| 먼 배경 | 지형과 석양의 공간 깊이, 차분한 공기 원근 | 연기·먼지·불꽃의 서로 다른 운동. 야영지 전체 오픈월드를 먼저 만들지 않음 |

16:10/16:9에서 구도·정보 패널의 안전 영역을 함께 검토한다. 창 크기/DPI를 바꿔도 인물의
얼굴과 주요 조작이 잘리지 않게 한다. 따뜻한 석양, 진홍색 직물, 상아색 지도, 청동의 작은
반사, 차분한 그림자로 시각 위계를 만든다. 조명 효과가 금융 정보를 압도하면 실패다.

직물의 부드러운 광반응, 목재 결, 청동의 반사/산화, 가죽의 마모, 석재의 거칠기를 구별한다.
물성·사용 흔적·실제 치수는 일관되게 만들고 모든 표면을 동일 노이즈나 과도한 광택으로 채우지
않는다. 천막 색·테이블 구성·상시 참모 배치는 작품의 창작 설정이며 특정 역사적 사령부의
정확한 복원이라고 주장하지 않는다.

### 선택 반응과 생활 동작

- 지도는 표식/손짓, 두루마리는 종이/끈의 움직임, 참모는 시선/자세, 군장은 재질에 맞는
  짧은 접촉음으로 반응한다. 모든 오브젝트에 같은 확대·빛 테두리·효과음을 붙이지 않는다.
- hover/키보드 초점, 선택 접수, 처리 중, 실제 완료를 구분한다. 계산 백분율이 없으면
  실제 단계와 실행 중 표시만 보여 준다. 장식 애니메이션이 완료돼도 분석 완료로 바꾸지 않는다.
- 천막·군기·불꽃·연기·먼지는 공통 바람의 영향을 받되 서로 다른 질량·감쇠·위상으로 움직인다.
  무작위 seed와 시간축을 기록해 검수 재현성을 확보한다. 모든 개체의 동기화된 왕복은 피한다.
- 인물의 시선→목→상체, 발·손·의자/테이블 접점, 의복 관통을 검사한다. 보행은 실제 rig의
  걸음과 root 이동을 맞추며 이미지 이동을 보행으로 세지 않는다.

### 현대 금융 정보와 음향

종목명·티커·원화 금액·비중·출처·기준 시각은 현대 금융 용어를 사용한다. 금액을 금화나
병력으로 치환하지 않는다. 지도는 공간적 선택 장치이며 정확한 수치는 화면 고정 2D 패널에서
읽는다. NPC 대사와 결과 표를 구분하고 출처·기준일이 없는 데이터는 미확인으로 표시한다.
Python이 전달한 exact 문자열과 원본 bytes의 의미를 유지한다.

긴 한글 이름은 확장/상세 보기/복사로 끝까지 읽을 수 있어야 한다. 티커의 선행 0, 원화 단위,
음수·소수·긴 비중 문자열, 출처와 시각을 검사한다. 본문 16–18 DIP 상당과 본문 대비 4.5:1을
설계 출발점으로 삼고 실제 폰트·DPI에서 재평가한다. Tab/Enter/Space/화살표·초점·스크롤을
지원하고 배경/피사계심도/빛 번짐이 텍스트를 흐리지 않게 한다.

처음에는 무음이며 사용자가 켠 뒤 환경·장치·인물/군마·음악/음성의 버스를 분리한다. P0 음향은
바람/천막·야영지의 짧은 환경 loop와 지도/문서 cue만으로 제한한다. 최소화 시 무음, 복원 시
자동 재생 없음. 헤드폰과 스피커에서 반복 이음새·클리핑·말소리/숫자 읽기 방해·피로를 직접
청취한다. 음향 상태 자동 테스트를 실제 청취 증거로 쓰지 않는다.

## 3. 다섯 AI 참모

아래 역할과 함께 활동하는 시공간은 팔랑크스의 창작 설정이다. 역사적 인물 모두가 이 구성으로
같은 원정 천막에 상주했다는 주장이 아니다. 외형·복식의 근거와 개성은 자산별로 기록한다.

| 참모 | 확정 역할 | 장기 실제 서비스 연결의 완료 기준 |
|---|---|---|
| 헤파이스티온 | 수석 참모·주 AI 비서·사용자 의사결정 보좌 | 질문/작업을 정리하고 하나의 공통 작업 상태와 결과로 안내. 사용자가 선택한 지원 기능을 실제 요청으로 연결 |
| 아리스토텔레스 | 전략·배분 알고리즘 설명과 비교 | 구현된 알고리즘/시나리오와 입력·제약에 근거해 설명. 존재하지 않는 알고리즘을 실행했다고 말하지 않음 |
| 프톨레마이오스 | 공시·리포트·뉴스·경제 지표 조사 | 실제 출처·발행/기준 시각·인용 범위를 갖춘 조사 결과를 제시. 외부 데이터 도입은 후속 기능 |
| 파르메니온 | 위험·집중도·손실 시나리오 검토 | 공통 분석 결과와 지원되는 진단/시나리오를 읽고 근거를 연결. 자체 숫자 사본이나 별도 계산 엔진 없음 |
| 네아르코스 | 산업·기업 후보 탐색 | 지원된 데이터와 검색 기능으로 후보를 구성하고 provenance를 유지. 미지원 탐색은 미지원으로 표시 |

최종 NPC는 반복 대사 장치가 아닌 실제 AI 비서다. 다만 **T0/P0에 AI 대화 서비스를 구현하지
않는다**. 첫 헤파이스티온은 실제 작업 이벤트에 반응하는 연출이며, 대사가 필요하면 시연/상태
안내임을 구분한다. AI가 연결됐다고 표시하지 않는다.

후속 AI는 공통 연결 어댑터의 허용된 도구만 사용한다. 질문→근거 조회→지원되는 변경안의
미리보기→사용자의 실행 선택→공통 Python 서비스→result ID와 근거가 붙은 응답으로 연결한다.
NPC마다 별도의 계산 서비스/원본 결과 사본을 만들지 않는다. 대화 요청과 분석 작업 ID를
분리해 대화 취소·NPC 교체가 금융 작업 취소로 해석되지 않게 한다. 모델/공급자·키 보관·비용·
외부 자료 접근과 장기 기억은 후속 결정이며 이번에는 설치·연결하지 않는다. 계좌 주문은 범위 밖이다.

## 4. 부케팔로스: 확정 등장, 독립 제작 단계

### 역사 기록과 창작 설정

고대 저술의 **전승**을 현대의 실측 외형이나 행동 데이터와 구분한다.
[아리아노스 『알렉산더 원정기』 5.19](https://www.gutenberg.org/cache/epub/46976/pg46976-images.html#Page_296)는
큰 체격·기개와 알렉산더와의 유대를 전하고, 이름의 유래에 낙인/머리의 흰 표식이라는 서로
다른 설명을 소개한다. 정확한 품종·키·얼굴·장비 색은 이 기록으로 확정할 수 없다.
[플루타르코스 『알렉산더전』 6](https://classics.mit.edu/Plutarch/alexandr.html)은 그림자를 두려워하는
말을 햇빛 쪽으로 돌려 진정시키는 일화를 전한다. 이를 역사적 일화로 참고하되 모든 대기 중
그림자에 놀라는 동작을 강제하지 않는다.

| 항목 | 이번 제작 제안 | 근거 구분 |
|---|---|---|
| 외형 | 힘 있는 체형, 짙은 털, 머리의 절제된 흰 표식을 후보로 콘셉트 검토 | 전승에서 영감. 정확한 형태/품종/체고는 창작이며 실측 사실로 쓰지 않음 |
| 성격 | 경계심은 있으나 익숙한 사용자에게 귀·눈·목으로 먼저 반응, 차분한 교감 | 사용자 인식·신뢰 표현의 구체 동작은 창작. 인간처럼 분석을 이해하는 역할 없음 |
| 장비 | 가죽 굴레·직물 안장깔개와 절제된 청동 장식의 초안 | 원정 시기 마구 도상/유물의 추가 조사 필요. 현대/중세 장구를 근거 없이 역사적 장비로 넣지 않음 |
| 행동 | 호흡·귀/꼬리·체중 이동, 고개 낮추기·접근/물러남·짧은 접촉 반응 | 말 해부/실제 행동 참조로 제작할 애니메이션. 기존 humanoid 모션을 그대로 적용하지 않음 |

### 제작 순서와 통과 조건

1. **첫 등장:** 입구 또는 마구간 한 구역에서 기다리는 말과 자연스러운 대기. 말 전용 rig,
   발굽 접지·관절·호흡·귀/꼬리의 독립 동작, 체형/털/장비 미술 승인. 전신 이동 없이도 살아 있는 인상.
2. **교감:** 사용자 접근 인식, 시선/귀 전환, 쓰다듬기. 손/목 접점·사용자 위치·중단/반복 입력을
   검사하고 말의 반응이 UI 명령/분석 상태와 혼동되지 않게 한다. 1–2는 사령부 시제품(P0) 다음 독립 제작 단계다.
3. **승하차·야영지 이동:** 인간/말 동기화, 착석·굴레·카메라·경로·정지/재개를 별도 검증한다.
4. **제한된 정찰/짧은 활동:** 범위가 정해진 장소와 활동만 확장한다. 전투·오픈월드 전체의 승인이 아니다.

승마 중에도 분석은 계속된다. 결과 알림 선택 시 말/탑승/활동을 안전한 상태로 정지·기록한 뒤
결과로 이동하고 복귀 시 해당 활동 상태를 재구성한다. 이 기능은 후속 설계/구현이며 현재 지원
기능으로 보고하지 않는다. 군마를 첫 지도 계산 실험에 끼워 넣지 않는다.

## 5. 공간과 분석을 분리하는 사용자 경험

입력 선택→지도에서 분석 요청→실제 처리 상태→결과 알림→결과 확인/원본 저장이 첫 순환이다.
장기에는 공간 이동·NPC 대화·미니게임·승마 중에도 **같은 분석 작업과 결과**를 유지한다.
완료 알림은 어디서나 보이고 선택하면 해당 결과로 바로 갈 수 있다. 자동으로 입력을 빼앗거나
다른 결과를 대신 열지 않는다. 실패/부분 결과를 전체 성공 연출로 표시하지 않는다.

분석 상태는 앱 세션 소유, 공간/인물은 표시 소비자다. 놀이/승마는 별도 checkpoint를 두고
알림 이동 전 안전한 tick에서 정지, 복귀 시 명시적으로 재개한다. 저장하지 않은 결과를 방
unload나 새 계산 때문에 지우지 않는다. 구체적인 ID·재조회·원본 보존·상한·종료 계약은
[기술 설계](../decisions/expedition-headquarters-rendering.md#작업과-화면의-수명-계약)에 한 곳에서 관리한다.
실행 중 앱 세션 보존과 crash/재부팅 후 복구는 다른 기능이다. 이번 계획은 후자를 보장하지 않는다.

## 6. 품질 단계와 미술 완료 기준

**고급**은 초고사양 목표의 대표 미술 기준이다. **기본**도 같은 세계관·캐릭터·장치의 매력을
갖춘 품질 단계로 검토하며 현재 보급형 지원의 약속은 아니다. 두 단계의 차이는 그림자/반사·
간접광·천/머리 표현·텍스처/LOD·효과 밀도 등 측정 가능한 설정으로 명시한다. 기본에서 인물
시선·손/발 접점·지도 반응을 제거하거나 현대 금융 UI를 축소해 통과시키지 않는다.

높은 미술 목표가 모든 고가 기능의 동시 사용을 뜻하지 않는다. cloth·연기 overdraw·skin/hair·
동적 광원 비용은 나눠 측정하고, 설정별 동일 구도·입력·동작의 화면과 실측치를 제출한다.

| 미술 항목 | 통과 기준 |
|---|---|
| 구도/분위기 | 열린 진홍 천막·중앙 목재/청동 테이블·상아색 지도·참모·석양 야영지가 한 화면에서 읽힘 |
| 재질/조명 | 직물·목재·청동·가죽·석재의 차이, 따뜻한 빛·차분한 그림자, 인물의 자연스러운 피부/눈/의복 |
| 인물/생활 | 시선·자세·손짓의 이유가 보이고 발/손 접점·관통·순간이동 결함 없음. 확대/이미지 이동으로 대체하지 않음 |
| 움직임/반응 | 천/군기/불꽃/연기/먼지의 서로 다른 움직임, 지도/문서/인물에 맞는 선택 반응 |
| 금융 UI | 긴 한글·티커·정확한 원화/비중·출처/시각을 편하게 읽고 복사/키보드 조작 가능 |
| 음향 | 오브젝트별 절제된 cue, 과도한 반복/클리핑 없음. 실제 헤드폰/스피커 청취 완료 |

정지 화면 3장(전체/인물 접점/정보 패널), 60초 이상 실시간 영상, 실제 선택 흐름과 청취 기록을
기본·고급 각각 제출한다. 항목별 1–5점 중 4 이상을 제안하며 평균으로 낮은 항목을 덮지 않는다.
사용자의 미술 검토를 포함한다. 임시 도형·기성 mannequin만이면 미술은 **미검증**이다.

## 7. 작은 첫 실험과 단계별 사용할 수 있는 버전

### T0 · 자산 없는 기술 연결 검증

가장 먼저 **빈 UE 장면 또는 임시 도형 → 별도 native Windows Python 프로세스의 실제 기존
계산 → 최소 결과 표시 → 정상 종료**를 검증한다. 확인된 노트북을 첫 측정 환경으로 사용한다.
유료 자산·외주 인력·DCC·완성 캐릭터·천막·음향은 T0의 선행 조건이 아니다. T0는 엔진/도구와
native Python 환경을 준비한 뒤 수행할 기술 실험이며 이번 문서 작업에서 구현하지 않는다.

기존 합성 입력 한 건과 최소 텍스트 UI로 실제 결과·상태를 확인한다. mock 응답이나 고정 대사로
계산을 대신하지 않는다. Editor의 개발 연결과 패키징한 Windows 실행본의 프로세스/파이프·정상
종료를 별도로 판정한다. T0 통과는 연결·계산·표시·종료의 증거이며, 사령부의 미술·음향·대표
장면 성능·지원 사양을 확정하는 증거가 아니다. 임시 도형의 미술 판정은 미검증으로 남긴다.

### P0 · 기존 사령부 시제품

T0 다음의 범위는 기존대로 대표 천막/테이블 일부, 헤파이스티온 한 명, 상호작용 지도 한 개,
천막 밖 야영지 일부, 기존 Python 실제 계산 한 건이다. 후경은 제한된 천막/군기·작은 환경
효과로 시작하며 대규모 병사 군중·전령 시스템·군마·자유 보행·미니게임·AI 대화를 추가하지 않는다.
[재현 입력과 T0/P0 절차](../decisions/expedition-headquarters-rendering.md#5-첫-실험의-실행-절차)를 따른다.

P0 판정은 세 가지로 남긴다.

1. **기능:** 기존 서비스와 계산/오류/정확한 표시·원본 저장/재열기가 일치한다.
2. **운영·성능:** 실제 Windows 실행본에서 장면과 분석을 동시에 실행하며 종료·복원·메모리·
   프레임/분석 시간을 측정하고 프로세스/파일 누수가 없다.
3. **미술:** 위 장면·인물·재질·반응과 실제 청취를 만족한다. 게임 조작의 매력도 이 판정에서
   직접 관찰하며 기능 통과로 대신하지 않는다.

| 단계 | 사용할 수 있는 결과 | 다음 단계 전제 |
|---|---|---|
| 0 · 현재 | 조사/설계 문서와 기존 Windows Desktop 사용 | 제품 코드는 이번에 바꾸지 않음 |
| T0 · 기술 연결 | 빈 UE 장면/임시 도형에서 native Python 실제 계산·결과 표시·정상 종료 | Editor와 Windows 패키지 각각의 기술 판정. 유료 자산·외주·완성 캐릭터 불필요, 미술·음향은 미검증 |
| 1 · 작은 사령부(P0) | 실제 입력→계산→표시→저장/재열기 가능한 한 공간 | 세 판정과 Windows 패키지 검증. 시험한 장면/입력/PC 범위만 보고 |
| 2 · 부케팔로스 | 입구/마구간의 등장과 교감 | 군마 전용 자산·접점·행동·분석과 공존 검증 |
| 3 · 실제 참모 보좌 | 헤파이스티온부터 근거 있는 질문/지원 기능 실행, 이후 네 참모 확장 | 공통 도구/작업 계약과 실제 AI 평가. 공급자/자료 권리/운영 비용 결정 |
| 4 · 생활 공간/놀이 | 공간·짧은 선택 놀이·승하차/이동을 한 단위씩 추가 | 작업 보존과 checkpoint·자원 경쟁 재검증 |
| 5 · 장기 확장 | 정찰 등 승인된 추가 활동, 품질 개선 | 실제 제작 능력·측정·사용 피드백으로 범위 결정 |

각 단계는 달력상의 연차 약속이 아니다. 5년치 기능을 첫 시제품에 합치지 않고 기존 계산을
쓸 수 있는 버전부터 쌓는다. 미래 하드웨어 가격/성능이나 5년 뒤 보급형 호환을 가정하지 않는다.
