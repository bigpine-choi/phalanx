# Phalanx Formation Room v1

Formation Room은 저장된 PR #23 allocation-targets JSON을 검증해 하나의 독립 HTML로 보여주는 오프라인 편성실이다. **위험자산 내부 연구용 배분**이며 실제 계좌 실행 목표·추천 포트폴리오가 아니다. 이번 화면은 추후 Windows 설치형 앱에 내장할 시제품이다.

```bash
uv run phalanx portfolio formation-room \
  --targets /absolute/private/allocation-targets.json \
  --output /absolute/private/formation-room.html
```

`--targets`와 `--output`은 필수이며 기존 호출은 그대로 동작한다. `--selection /absolute/private/selection.json`을 선택적으로 추가하면 원본 선정 결과의 종목명을 연결한다. 각 입력은 제한 크기로 한 번씩 읽고 원본을 변경하지 않는다. HTML은 기존 원자 저장 경계를 사용하며 기존 파일을 덮어쓰지 않는다. DB·API·계좌·자격증명·위험모형·solver는 호출하지 않는다. 브라우저 자동 실행, 브라우저 내 JSON 재업로드, 서버, CDN, 외부 폰트, telemetry, JS 빌드 체인은 없다. 입력 처리·화면 모델·렌더링·CLI와 HTML/CSS/JS 원본을 분리하고, 출력 HTML에는 필요한 자산을 모두 포함한다. 패키지 설치 후에도 패키지 자산을 사용한다.

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 유효한 저장 결과를 HTML로 생성; 미준비·계산 실패·부분 성공 화면도 포함 |
| 65 | 잘못된 JSON 또는 화면 입력 계약 위반 |
| 66 | 입력 읽기·출력 저장 오류 또는 기존 출력 파일 존재 |
| 70 | 예상하지 못한 내부 화면 생성 오류; 원본 예외·traceback은 출력하지 않음 |

## 화면과 수치

상단은 입력 파일명·선정일·실제 계산일·전체 상태를 보여준다. 선정일은 휴일일 수 있으므로 계산일과 따로 표시한다. 얇은 상태줄에는 선정 종목 수·수익률 관측 수·성공 시나리오 수가 있고, 네 탭 각각에 해당 시나리오의 추정 연환산 변동성이 있다. 미산출 수치를 0으로 채우지 않는다.

네 탭의 순서는 기존 `SCENARIO_KIND_ORDER`를 따른다.

1. `long_run_ledoit_wolf`
2. `fast_iewma`
3. `slow_iewma`
4. `downside_stress_ledoit_wolf`

첫 번째 탭을 기본으로 열며 추천·최적 시나리오는 지정하지 않는다. 종목 카드와 상세는 `selected_codes` 순서다. 탭을 바꿔도 선택 종목을 유지하고, 실패 탭에서는 이전 성공 비중을 지우고 실제 저장 실패 사유를 보여준다. 카드의 목표비중과 상세의 상대 위험기여도·상한 적용 상태를 구분한다. 상대 위험기여도는 음수일 수 있으며 0이나 절댓값으로 바꾸지 않는다. 상세에는 가격 관측 수·최근 적격일도 포함한다. 회사명은 해시로 연결된 원본 selection의 selected 후보에 있는 이름만 사용한다. 선택 파일 미제공·원본 이름 없음은 `이름 미확인`과 종목코드로 표시한다. 업종·선정 점수·선정 이유·계좌 NAV를 새로 만들거나 조회하지 않는다.

성공 시나리오에는 전체 위험자산 100% 구성을 수평 누적 막대로 보여준다. 색상과 순서는 종목코드를 기준으로 네 시나리오에서 유지한다. 구간과 카드는 같은 선택·상세를 공유하며 키보드로 탐색할 수 있다. 구간의 접근성 안내와 근거 목록에 원본 Decimal 비중을 제공한다. 전체 구성도는 100% 기준이고, 카드의 개별 막대 전체 길이는 종목당 20% 상한 기준이다. 원본 비중을 재정규화하지 않으며 JS는 검증된 값의 시각적 길이에만 사용한다. 실패 탭은 이전 구성도·비중·위험 수치를 지운다.

계산 근거를 펼치면 관측 시작·종료, 준비/계산 실패 사유, 핵심 fingerprint, 원본 Decimal 비중 문자열과 데이터 한계를 확인할 수 있다. 입력 파일 SHA-256은 같은 파일을 식별하는 값이며 진위 인증이 아니다. 전체 수익률 행렬과 공분산은 HTML에 복제하지 않는다. HTML에는 종목·비중 등 화면용 정보가 포함되므로 실제 결과 HTML도 private 자료로 취급한다.

## 화면용 projection 입력 계약

이 파서는 기존 `AllocationTargets` 전체 역직렬화나 위험모형 재계산을 수행하지 않는다. **표시할 필드와 상태 간 연결을 검증하는 projection parser**다. 공분산 재산출·KKT 재계산·원천 가격 해시 재검증을 했다고 주장하지 않는다. features 소비 해시의 기존 미검증 상태도 바꾸지 않는다.

UTF-8과 **32 MiB** 파일 크기 제한을 적용하고, 중복 JSON 키·NaN/Infinity·잘못된 필수 타입·schema/version을 거부한다. 파일은 최대 32 MiB + 1 byte만 읽어 초과 여부를 판단한다. `bool`을 숫자로 받아들이지 않는다. `research_scope`, `account_execution_target=false`, `recommended_scenario=null`을 확인한다. 코드 중복·순서와 prepared 연결, 네 시나리오 순서, 전체 status·complete·succeeded_count와 시나리오 상태의 일치를 검사한다.

`input_unavailable`, `common_failure`, `succeeded`, `partial`, `failed`를 지원한다. 성공 target은 해당 시나리오에 연결되어야 하며 실패 target은 null이다. 계산 가능한 결과의 calculation_date·reference_price_date·prepared.used_end와 target의 날짜·종목 순서를 대조한다. 정상 미준비 결과의 null 날짜와 영숫자 종목코드는 허용한다.

`reconciled_decimal_weights`는 원본 Decimal 문자열로 읽는다. 고정 `financial_decimal_context` 안에서 길이·양수·20% 상한·bounds·정확한 합계 1을 검사하며 재정규화하지 않는다. 표시 변동성·위험기여도·bound_flags는 `diagnostics_after_reconciliation`에서 읽고 길이·유한값을 검사한다. 퍼센트 문자열은 Python에서 만들고 원본 비중 문자열도 보존한다. JavaScript Number는 막대 길이 등 시각 표현에만 사용한다.

입력 문자열은 HTML escape 또는 DOM `textContent`로 삽입한다. 데이터 기반 `innerHTML`·`insertAdjacentHTML`·`eval`은 사용하지 않는다. 인라인 JSON의 `<`, `>`, `&`, `</script>`, U+2028/U+2029를 안전하게 인코딩한다.

## 원본 선정 결과의 이름 연결

선택적인 `--selection`도 32 MiB + 1 byte까지만 한 번 읽는다. 제공된 원본 bytes의 SHA-256이 **`targets.prepared.selection_file_sha256`**과 일치할 때만 기존 `allocation_input.validation.parse_selection`을 호출한다. `selection.source.input_sha256`은 features 파일 해시이므로 이 비교에 사용하지 않는다.

선정 코드·순서·기준일·참조 가격일, source·정책·선정 완료 근거와 종목별 원천 해시·관측 근거가 targets의 prepared와 연결되는지도 대조한다. 이름은 `selection.candidates`에서 `status="selected"`인 후보의 `target.name`만 `target.short_code`로 연결한다. 이 검증은 저장 파일 간 대응 확인이며 외부의 실제 회사명 인증이나 features 해시 재검증은 아니다.

해시 불일치·잘못된 selection·대응 근거 불일치는 입력 오류 65, 읽기 실패는 66이다. 긴 이름·중복 이름은 유지하고 `None`/공백 이름은 미확인으로 표시한다. 회사명을 크게, 코드를 작게 표시하되 모든 선택·색상·연결의 고유 키는 종목코드다. 이름 문자열도 DOM textContent와 안전한 JSON 삽입을 사용한다.

합성 예제 생성기는 원천 history target 단계에서 가상의 이름을 부여한 뒤 실제 features→selection→targets 경로를 실행한다. 완료된 selection이나 해시를 사후 편집하지 않는다. 표현 메타데이터 `FormationRoomPresentation(synthetic_demo=True)`를 명시적으로 전달하므로 모든 생성 예제에 **합성 데이터 데모** 배지가 표시된다. 일반 입력의 실제/합성 여부를 파일명으로 판단하지 않는다. `no-selection` 예제만 옵션 미제공 호환 검증을 위해 연결을 생략하며, 나머지는 생성한 원본 selection을 연결한다.

## 조작과 음향

짙은 남청색과 청록·금색 강조, 한글 상태 텍스트·정렬된 숫자로 저장 결과의 비교와 종목 상세 탐색을 돕는다. 화면 전환은 짧게 유지하며 키보드 포커스와 모션 축소를 지원한다. 매수/매도 버튼, 비중 수동 변경, 가짜 메뉴·진행률은 없다.

화면의 중심은 위험자산 전체 구성과 기업명이다. 상단 파일·관측 정보는 보조 위계로 정리하고, 기업명·핵심 비중·설명·종목코드의 크기와 굵기를 구분한다. 남청색 배경 위에서 패널과 선택 카드의 명도·여백으로 구역을 구별하며 반복 테두리와 영문 장식을 줄인다. 종목별 색상은 식별용으로 유지하고 선택 강조는 현재 종목에만 적용한다.

구성 구간·카드·상세는 같은 선택 상태를 즉시 공유한다. 짧은 시각 전환과 효과음은 동일한 선택 동작에 연결하며, 모션 축소와 최초 무음을 유지한다. 금융 수치는 전환을 위해 보간하거나 임의의 중간 값으로 표시하지 않는다.

효과음은 종목 선택·시나리오 전환·근거 패널·설정 확인·결과 조회·주의 상태 같은 실제 동작에 연결한다. hover마다 재생하지 않고 빠른 연속 클릭의 중첩을 제한한다. 배경음은 코드에 정의한 선율·화성과 부드러운 합성 악기로 만든 앰비언트 루프다. **코드로 합성한 프로토타입 배경음악**이며 전용 음악 생성 도구가 만든 AI 작곡 완성곡으로 설명하지 않는다. 음향 계층을 분리해 후속 정식 음원으로 교체할 수 있게 한다.

처음에는 무음이다. `AudioContext.resume()`이 대기하면 화면에 시작 대기 상태를 표시하고 전체 무음/취소 버튼을 계속 사용할 수 있다. 취소하면 generation을 갱신하여 뒤늦은 resume 완료·실패가 재생을 시작하거나 새 요청을 변경하지 못하게 한다. 명시적으로 소리를 켜거나 미리듣기를 실행한 뒤에만 소리를 낸다. 전체 무음, 효과음·배경음 개별 음량, 음악 시작·정지를 제공한다. 저장된 ON 설정이 있어도 새로 연 페이지에서 자동 재생하지 않는다. 음향·모션 설정만 localStorage에 보관하고 투자 데이터는 저장하지 않는다. `file://`에서 저장이 막히면 세션 설정으로 계속 동작하며 화면에서 안내한다.

페이지가 숨겨지면 음악과 예약 음원을 멈추고 돌아온 뒤에는 사용자가 직접 재개한다. 정지·재시작 때 예약 타이머와 노드를 정리한다. 기본 음량은 낮게 설정하며 gain envelope로 급격한 클릭·피크를 줄인다. Web Audio 미지원·권한·장치·재생 실패가 화면 탐색을 막지는 않는다. 실제 음색·음량과 `file://` 저장 허용 여부는 브라우저·OS·출력 장치에 따라 달라진다.

## 실행·검증·후속 범위

[합성 예제](../examples/formation-room/README.md)는 실제 PR #23 계산 경로로 성공 6종목·5종목 경계·미준비·공통 실패·전체 실패·부분 성공을 재현한다. 부분 성공 예제의 한 solver 실패 주입은 별도 manifest에 명시한다. JSON을 사후 편집해 성공/실패를 꾸미지 않는다.

WSL에서는 사용자가 다음 명령으로 출력 폴더를 Windows 탐색기에서 열고 HTML을 선택한다.

```bash
explorer.exe "$(wslpath -w /tmp/phalanx-formation-demo/succeeded)"
```

WSL 파일 경로를 브라우저가 열지 못하면 HTML 한 파일을 Windows의 새 폴더에 복사해 연다. 브라우저 서버 실행이나 인터넷 연결은 필요 없다. CLI는 브라우저를 자동 실행하지 않는다.

Python 검사와 브라우저·오디오 검증은 별개다. 검토 ZIP의 `REVIEW_CONTEXT.txt`에 실제 실행한 Ruff·mypy·전체 pytest·포맷·diff 검사 결과와 브라우저 동작·화면 캡처·청취의 확인 범위 및 미검증 항목을 기록한다. 정적 문자열 검사를 실제 브라우저 검증으로 대체하지 않는다. 선택적 `tests/browser/verify_formation_room.py`는 별도 Playwright Python 환경에서 실제 Chromium을 실행한다. 제품에 Playwright 의존성이나 JS 빌드 체인을 추가하지 않는다. 설치·실행 명령과 사용자가 직접 확인할 1440×900/1280×720·키보드·실패/부분 상태·설정·외부 요청·콘솔·음향 절차는 합성 예제 문서에 있다.

기존 숫자 코드 계산 제한, 공식 거래일 무누락 미검증, point-in-time 미보장, 배당 제외 수정주가 한계를 유지한다. 영숫자 코드가 포함된 정상 미준비 결과는 그 사유와 함께 조회할 수 있다. 저장 결과를 실시간 분석으로 연출하지 않는다. 이번에는 설치 프로그램·서버·새 JS 빌드 체인·실계좌 연결·추천·주문 기능을 만들지 않는다. 후속 Windows 앱에서는 현재 화면 모델과 자산을 내장하고, 호스트의 파일 선택·설정 저장·정식 음원 계층을 연결할 계획이다.

## 검증 기록

초기 검토본은 pytest 2,375개였다. 시각 개선을 포함한 이번 최종 코드에서 전체 pytest를 한 번 실행하여 **2,406개 통과(36.02초)**를 확인했다. Ruff, mypy `src` 124개 파일, 변경 Python 18개 파일 포맷 검사를 통과했다. 전체 diff 검사와 패키지 자산·설치 후 HTML 일치도 확인했다.

실제 Chromium에서 11개 합성 사례의 이름·원본 비중·구성도·키보드·실패 상태와 일반 CLI 호환을 검사했다. 음향은 실제 UI 대기 취소와 취소/재시작 경쟁 상황을 포함한 13개 범주를 통과했다. 외부 요청·콘솔 오류는 0이었다. 1440×900·1280×720, 긴 이름·이름 미제공·부분 실패·설정 화면의 수정 전후 캡처, 실행 로그와 전체 패치는 검토 ZIP의 `REVIEW_CONTEXT.txt`와 `review-artifacts/`에 포함한다.

실제 스피커·헤드폰 청취, Windows 브라우저/설치형 앱, OS 탭 숨김은 미검증이다. 숨김·복귀/BFCache는 실제 브라우저 안에서 이벤트를 주입해 확인하며 이를 실제 OS 전환이나 청취로 간주하지 않는다. 음향 시작 대기 취소는 controller 직접 호출 외에 **실제 UI 버튼 클릭**으로 대기→취소→resume 완료를 검사한다.

기능 검사와 별도로 실제 화면의 정렬·한글 가독성·시선 흐름을 검수했다. v2와 개선본의 화면 데이터가 바이트 단위로 같은지 확인한 뒤 동일 시나리오·선택 종목·설정·뷰포트에서 캡처했다. 1440×900·1280×720의 성공·긴 이름·이름 미제공·부분 실패·설정 **10쌍·20개 캡처**를 만들고, 측정한 크기·정렬 정보와 직접 검수 의견을 구분해 기록했다. 카드 기업명은 16px에서 18px로, 선택 상세 이름은 두 뷰포트에서 각각 23→25px·22→24px로 확대했다. 상단을 줄여 구성 패널은 각각 약 49px·21px 위에서 시작한다. 긴 이름은 단어 단위 줄바꿈과 세로 스크롤을 유지한다.

비교 스크립트는 `tests/browser/verify_formation_room_visual.py`이고, 캡처·비교 갤러리·판정 근거는 v3 검토 ZIP에 포함한다. 실제 UI 클릭 시 구성도·카드·상세의 코드와 색상 반영 뒤 효과음이 호출되는지, 동일 선택 재클릭은 전환·효과음을 반복하지 않으면서 키보드 포커스 이동을 유지하는지도 확인했다.
