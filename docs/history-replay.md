# 저장 일봉의 수집 시각을 검사하는 후보 선정 재실행

`phalanx candidates replay-history`는 명시한 일봉 작업의 저장 결과를 한 번 읽고, 종목별 수집 완료 시각을 판단 시각과 대조한 뒤 가격 특성값과 후보 선정을 다시 계산한다. 계좌 조회, 네트워크 호출, 주문은 수행하지 않는다. 기존 `candidates replay`의 외부 선언 명세와 별개의 경로다.

```bash
uv run phalanx candidates replay-history \
  --history-db /absolute/private/history.sqlite3 \
  --job-id JOB_ID \
  --as-of 2026-09-11 \
  --decision-at 2026-09-13T09:00:00+09:00 \
  --code 005930 --code 0001A0 \
  --metric return_60 --top 1 --max-age-days 2
```

`--job-id`는 정확한 저장 작업을 지정한다. 다른 작업이나 가장 최근 작업으로 자동 대체하지 않는다. `--code`는 반복할 수 있으며 해당 작업의 종목 1~25개를 명시해야 한다. 더 큰 작업을 여러 묶음으로 나누면 각 선정 순위는 그 묶음 안에서만 유효하며 통합 순위로 해석할 수 없다. `--metric`, `--top`, `--max-age-days`는 [기존 후보 선정 정책](candidate-selection.md)을 그대로 사용한다. `--as-of`는 특성값 계산에 사용할 마지막 거래일이고, `--decision-at`은 시간대가 포함된 판단 시각이다. 두 날짜를 같은 뜻으로 취급하지 않는다. `--output`으로 새 개인 JSON 파일에 결과를 저장할 수 있으며 기존 파일은 덮어쓰지 않는다. 이 명령의 저장소 경로는 현재 Linux 실행 환경을 대상으로 한다.

## 수집 영수증과 사용한 행

저장소는 선택한 종목의 결과와 시도 이력을 한 SQLite 읽기 스냅샷에서 가져온다. 완료된 종목에는 결과와 일치하는 마지막 성공 시도의 `started_at`·`finished_at`이 있어야 한다. 정상적인 빈 응답은 빈 결과와 `empty` 시도로 구분한다. 시도 시각이 없거나 순서가 뒤집혔거나 `finished_at`이 `decision_at`보다 늦으면 이 재실행을 거부한다. 일부 종목만 앞선 시각에 수집됐다는 이유로 뒤늦게 수집한 종목을 숨기지 않는다.

각 종목의 저장 일봉 전체에는 기존 `HistoryResult.sha256` 검증을 적용한다. `as_of` 이하의 행 중 실제 특성값 계산에 사용한 최대 253개 행에 대해서는 종목코드, 거래일, 정확한 OHLCV 값의 행별 SHA-256과 해당 종목의 수집 완료 시각을 결과에 기록한다. 행별 해시는 같은 거래일의 수정 가격을 다시 수집했을 때 값이 달라졌는지 식별하는 데 쓰인다. 특성값의 `consumed_input_sha256`은 기존처럼 계산에 사용한 날짜·종가 입력을 식별하고, 전체 가격 결과의 해시와 행별 해시는 별도로 보존한다.

거래일은 가격이 가리키는 날짜이고 `finished_at`은 이 프로그램의 KIS 조회가 끝난 시각이다. 조회가 끝난 날짜보다 미래인 거래일은 일관성 오류로 거부한다. `as_of`가 판단일보다 미래여도 거부한다. 시각 비교에는 시간대가 포함된 값을 사용하고, 판단일·거래일 비교에는 `Asia/Seoul` 날짜를 사용한다. 검사를 통과하면 같은 저장 행으로 가격 특성값을 재계산하고 기존 단일 지표 선정기를 실행한다.

## 결과 해석의 한계

`finished_at ≤ decision_at`은 **로컬 수집 완료 시각 검사**다. 현재 `finished_at`은 DB 저장 전에 생성된다. 따라서 수집은 판단 전에 끝났더라도 저장 트랜잭션의 커밋이 판단 뒤에 끝났을 수 있다. 이 경로는 그 사이에 행을 프로그램이 실제로 읽을 수 있었음을 증명하지 않는다.

KIS의 과거 수정주가 응답에는 각 행의 최초 공표 시각이나 공급자 수정 버전이 없다. 이 기능은 저장 작업 ID, 수집 시도와 정확한 가격 행을 연결하지만, 과거 시장 참여자에게 그 가격이 언제 제공됐는지는 확인하지 못한다. 이후 수집 작업에서 과거 행이 바뀌어도 이전 작업을 덮어쓰지 않으며, 나중 버전의 가격으로 과거 판단을 조용히 다시 계산하지 않는다. 현재 discovery 후보를 과거 유니버스로 소급하는 생존편향과 거래일 누락 가능성도 해소하지 않는다.

결과의 `decision_at`은 검토하려는 과거 판단 시각이고 `replayed_at`, `features.calculated_at`, `selection.evaluated_at`은 **지금 다시 계산한 시각**이다. 따라서 과거에 특성값이나 선정 결과가 실제로 생성됐다는 뜻이 아니다. 기존 `candidates replay`의 선언 명세 검사와 달리, 이 명령은 저장 일봉에서 특성값을 새로 계산한다.

결과는 이 검사의 근거를 **로컬 수집 영수증**으로 표시하고 `point_in_time_backtest_guaranteed=false`를 유지한다. `history_results_rehashed_during_replay=true`는 이 경로가 저장 가격 결과를 다시 해시했다는 뜻이다. 내부 `selection.source.source_price_hashes_verified=false`는 기존 단일 지표 선정기 자체가 원천 저장소를 열지 않는다는 기존 계약이며, 두 필드의 검증 범위가 다르다. `row_evidence_sha256`은 결과에 담긴 행 목록의 자체 해시이지 공급자 서명이 아니다. 수익성 검증, 비용 반영 성과, 실거래 가능성과 전략 승격의 근거로 단독 사용하지 않는다. 공급자 행별 이용 가능 시각과 수정 이력, DB 커밋 이후의 이용 가능 시각을 확보해야 더 강한 시점별 검증을 주장할 수 있다.

완전 결과는 종료 코드 0, 정상적인 부분 선정 결과는 2, 잘못된 입력·수집 기록은 65, 저장소 또는 출력 파일 오류는 66이다.
