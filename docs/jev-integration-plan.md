# Jev 활용 개발계획

작성·공식 문서 확인: 2026-09-30 KST  
상태: 구현 전 설계. API 설치·호출·비용 발생·모델 평가·제품 기능 활성화는 수행하지 않았다.

## 1. 목표와 적용 위치

TypeSafe AI의 Jev를 기존 Python 서비스에서 호출하는 **교체 가능한 판단 모듈**로 검토한다. 첫 목표는 한국어 뉴스·공시의 사건 분류를 기존 방식보다 효율적으로 처리하는 것이다. 뉴스 분류의 성능과 투자수익 개선은 별도로 검증한다.

[기존 코드 활용 로드맵](legacy-reuse-roadmap.md)의 R6 뉴스 정찰을 구체화한다. R1 데이터 명세·R2 비교 검증과 기존 제품 M1 화면 개발의 우선순위는 유지한다. 소규모 분류 실험은 고정된 자료로 병행할 수 있으며, 전체 뉴스 수집기 완성을 기다릴 필요는 없다.

[네 엔진](four-engine-architecture.md)에서 연구는 분류·정성 특징 후보, 검증은 비교 평가, 감시는 오류·지연·입력 변화 관찰을 맡는다. 운용 엔진은 검증된 데이터 계약을 통해서만 결과를 받는다. Jev를 별도 다섯 번째 엔진이나 모든 요청의 필수 경유지로 만들지 않는다.

## 2. 확인한 기술 범위

공식 문서는 Choice(선택과 확률분포), Score(정의된 단계의 평가), Noul(참 여부의 확률)을 제공한다. 같은 입력에 대한 독립 질문은 한 요청에 묶을 수 있다. 한 질문의 답이 다음 질문의 입력을 바꾸는 경우는 별도 단계로 처리한다.

Choice·Score의 `confidence`는 확률분포의 모양을 요약한 수치다. 0.9를 정답률 90%나 투자 성공확률 90%로 해석하지 않는다. Jev 1.13 공식 한계에는 산술·날짜 비교·복잡한 간접 추론·무관한 긴 입력·악의적인 입력의 영향이 포함된다. 출력 형식의 제약이 판단 내용의 진실성을 보장하지 않는다.

Python이 날짜·수익률·NAV·비중·현금·한도를 계산하고, 생성형 AI가 참모 대화와 설명을 작성한다. Jev는 범위를 정한 의미 판단을 맡는다. API 접근 가능 여부, 사용 모델과 호출 조건, 한국어 금융 문서 성능·한국에서의 지연은 구현 시 확인한다. 사업자의 속도·비용 홍보 수치를 제품 성능으로 사용하지 않는다.

## 3. 단계별 범위

| 단계 | 개발 항목 | 산출물·완료 기준 |
| --- | --- | --- |
| J0 | 분류 기준·자료·평가 계약 고정 | 사건 분류표, 고정 입력 스냅샷, 사건별 그룹, 라벨과 분할, 비용·품질 기준 |
| J1 | Python 판단 인터페이스와 Jev 어댑터 | 가짜 응답으로 계약 검증, 제한된 실제 호출 실험, 오류·보류·로그·캐시 |
| J2 | 규칙·현재 LLM·Jev 비교 | 고정 평가셋 보고서, 선택적 자동 처리 정확도·처리율, 비용·지연과 채택/보류 사유 |
| J3 | 뉴스 화면에 제한 적용 | 사건별 분류·검토 대기 표시, 원문 이동, 수정 기록, 기존 경로 복귀 |
| J4 | 정성 정보를 투자특징으로 연구 | 문서 특징을 기존 가격·재무 입력과 비교, 시간 순서 평가와 이후 모의 관측 |
| J5 | 참모 요청 분류·설명 점검·게임 행동 | 필요성이 확인된 기능부터 별도 평가. 첫 실험의 완료 조건에 포함하지 않음 |

이번 최초 구현 범위는 J0–J2다. J3는 채택 기준 통과 이후 진행하고 J4·J5는 후속 연구로 둔다.

## 4. 첫 실험 JEV-01 — 뉴스·공시 사건 분류

### 4.1 입력과 정답 정의

처음에는 허용된 경로로 확보한 공개 한국어 기사·공시 약 300건을 사용한다. 기존 수집 코드의 제목만으로 결론을 낼 수 없는 경우, 동일한 원문 발췌를 세 비교 방법과 라벨 작성자에게 모두 제공한다. 사람이 전문을 보고 모델은 제목만 보는 평가를 금지한다.

분류 후보는 실적, 자본변동·조달, 사업·계약, 규제·소송, 거시·업황, 기타, 복합사건, 정보부족이다. 구현 전 작은 개발 표본으로 경계·예시를 정하고 버전으로 고정한다.

- 제목과 리드에서 중심으로 다루는 사건을 우선한다. 서로 다른 주요 사건이 동등하게 포함되어 한 가지를 정할 근거가 없으면 복합사건으로 분류한다.
- 정보부족은 제공된 입력 자체로 분류하기 어려운 정답 라벨이다. 모델의 낮은 확신 때문에 검토로 보내는 처리 상태와 구분한다.
- 중요 검토 사건은 별도의 사람 라벨로 관리한다. 초기 후보는 유상증자·거래정지·회생·감사의견 변경이며, 구체적인 포함·제외 기준을 개발셋에서 고정한다. 나쁜 투자라는 판단과 동일시하지 않는다.
- 라벨 근거가 된 문장·입력 범위를 보존한다. 애매한 표본은 2차 검토하거나 모호성 사유를 남기며, 모델 간 합의를 정답으로 삼지 않는다.
- 기업·종목 후보 매칭은 기존 식별자 처리로 선행한다. 모호한 기업명은 검토 대상으로 남기고 Jev가 임의의 종목코드를 생성하게 하지 않는다.

### 4.2 시점·중복·분할

목표 분할은 개발 200건과 시간상 이후의 잠금 평가 100건이다. 규모는 초기 탐색 목표이며 충분한 표본을 확보하지 못하면 아래 채택 기준을 통과했다고 판정하지 않는다.

기사 전재·동일 공시·동일 사건의 후속 보도는 사건 그룹으로 묶는다. 날짜 경계를 가로지르는 그룹의 앞부분은 개발셋에서 제외하고 이후 표본만 평가에 두거나 그룹 전체를 평가에서 제외한다. 같은 사건을 양쪽에 나누지 않는다. 개발·평가에서 고유 사건 수와 중복 기사 수를 각각 보고한다.

모델에게는 해당 입력 스냅샷과 분류 기준만 제공하고 이후 결과·가격 반응은 제공하지 않는다. 텍스트 분류 평가에서의 시점 분리는 모델 사전학습의 역사 지식 혼입까지 제거한 증거가 아니다. 투자특징의 유효성은 J4의 이후 시점 관측으로 따로 확인한다.

라벨·질문·임계값·모델·설정은 개발셋에서 결정한다. 잠금 평가를 본 뒤 바꾸면 해당 평가는 개발 이력으로 전환하고 새로운 평가 자료를 확보한다. 무제한 프롬프트 튜닝을 피하며 최초 실험의 기준 보완은 개발셋에서 최대 세 차례로 제한한다.

### 4.3 비교 대상과 지표

동일한 입력·정답·분류표에 대해 단순 키워드 규칙, 현재 사용하는 LLM의 구조화 분류, Jev를 비교한다. LLM 모델·추론 설정도 고정한다. 분류를 위해 추가된 검색·번역은 별도 조건으로 분리한다.

| 지표 | 정의 |
| --- | --- |
| 전체 분류 품질 | 잠금 평가셋 전체의 Macro-F1·클래스별 정밀도/재현율·혼동행렬. 판단을 보류한 표본도 원래 예측으로 평가하며 API 오류를 분모에서 제거하지 않는다. |
| 중요 사건 포착률 | 사람 라벨이 중요 사건인 전체 표본 중 중요 또는 검토 대상으로 전달된 비율. 정확히 자동 분류한 비율, 중요 판단 정밀도, 전체 중요·검토 전달률도 별도로 보고한다. |
| 자동 수용 정확도 | 검토 없이 수용한 표본 중 정답 비율. 자동 수용률은 전체 중 자동 수용된 비율로 따로 기록한다. |
| 확률·확신 진단 | 클래스 확률의 보정 오차와 confidence 구간별 실제 정확도·처리율. confidence를 성공확률로 치환하지 않는다. |
| 운영 비용 | 전체 처리와 자동 수용 1건당 비용, 재시도·실패·추가 LLM 호출·검토 건수. 수작업 소요시간은 별도 표시한다. |
| 속도·가용성 | 동일 장비·네트워크·동시성에서 종단간 p50/p95, 타임아웃·실패·보류율. 최초 호출과 캐시 적중을 나누어 보고한다. |

성능 수치에는 분자·분모·고유 사건 수와 불확실성 구간을 함께 표시한다. 비율 지표에는 Wilson 구간 등 적절한 구간을, 방법 간 비교에는 사건 그룹 단위의 재표집을 검토한다. 초기 300건으로 안정적인 운영 정확도나 투자 알파가 입증됐다고 하지 않는다.

### 4.4 제한된 화면 시범 적용의 채택 기준

아래는 **초기 제안값**이다. 데이터 확인 후 개발셋에서만 확정하고 잠금 평가 전 고정한다. 결과가 나온 뒤 통과시키기 위해 완화하지 않는다.

- 전체 Macro-F1 0.85 이상.
- 중요 사건 포착률 0.95 이상이고 평가 중요 사건이 최소 30건. 중요 판단 정밀도는 0.80 이상을 초기 목표로 두며, 전체 중요·검토 전달률의 허용 상한도 J0에서 고정한다. 모든 문서를 중요 또는 검토 대상으로 보내는 정책은 채택하지 않는다. 중요 사건의 자동 분류 정확도도 별도로 공개한다.
- 자동 수용 정확도 0.95 이상, 자동 수용률 50% 이상, 자동 수용 평가 표본 최소 50건. 전부 보류하여 높은 포착률만 얻는 방식을 채택하지 않는다.
- 최소 표본 30건·50건은 고유 사건 기준으로 센다. 주요 클래스가 평가셋에 없거나 최소 표본이 모자라면 증거 부족으로 보류한다. 추후 표본 확대 기준·추가 평가기간을 결과 확인 전에 정한다. 중요 사건을 과표집했다면 구성비를 공개하고 처리율·비용을 일반 운영 분포의 추정치로 확대하지 않는다.
- 기존 방법도 품질 조건을 통과하면, 전체 Macro-F1·중요 사건 누락을 악화시키지 않으면서 재시도·대체 처리까지 포함한 비용이 30% 이상 낮거나 p95 지연이 30% 이상 짧아야 한다. 비교할 기준 방법과 비용 산정 범위를 잠금 평가 전에 정한다.
- Jev만 품질 조건을 통과하면 J0에서 미리 정한 절대 비용·p95 지연·검토 부담 한도 안에서 제한 적용 여부를 판단한다. 이 한도가 비어 있으면 평가를 시작하지 않는다. 품질 개선과 속도·비용 개선의 채택 경로를 구분해 기록한다.
- 단순 규칙이 같은 품질을 더 낮은 비용·지연으로 달성하면 규칙을 유지한다. API 접근이 없거나, 이점이 없거나, 반복 보완에도 오류가 남으면 통합을 보류하고 기록을 보존한다.

이 기준은 뉴스 화면의 제한 시범 적용만 판단한다. 실제 투자 판단·주문 권한을 부여하는 기준이 아니다.

## 5. Python 입력·출력 계약

아래는 **팔랑크스가 정의할 내부 계약**이며 TypeSafe API 응답을 그대로 흉내 낸 스키마가 아니다. 실제 구현 시 기존 패키지·저장 구조에 맞춰 위치를 정한다.

| 객체 | 필수 내용 |
| --- | --- |
| `NewsDecisionInput` | 문서 ID·종류·원문 URL·매체, 제목·제공한 본문 범위, 원문 해시, 게시/수집/이용가능시각·시간대, 판단 기준시각, 사건 그룹, 검증된 기업 후보, 입력·분류표 버전 |
| `NewsDecisionResult` | 사건 라벨과 전체 선택 확률, 원래 confidence, 중요 검토 판단의 Noul 값, 처리 상태, 검토 사유, 원문 근거 참조, 요청 ID, 실제 반환 모델 버전, 질문·어댑터·정책 버전, 지연·사용량 |
| 처리 상태 | `accepted / review_required / unavailable / failed`. 정보부족·복합사건·낮은 확신·판정 불일치는 검토 경로로 보낸다. |
| 근거 참조 | 원문 ID와 미리 추출한 문장 ID/범위. 설명 문장 생성은 별도이며, 선택한 문장이 실제 원문에 존재하는지 코드로 검사한다. 초기 버전은 제공한 전체 발췌 범위를 근거로 표시할 수 있다. |

기본 질문은 중심 사건 Choice와 중요 검토 사건 해당 여부 Noul이다. 동일 state의 질문은 묶고 각각 완전한 지시·판정 기준을 쓴다. 내부 질문 ID만으로 의미를 전달하지 않는다. 알려진 선택지에 맞지 않는 입력도 처리할 수 있도록 기타·복합·정보부족을 둔다.

서로 충돌하는 답변을 코드에서 탐지해 검토로 보낸다. 확률의 범위·합, 유한값, 알려진 라벨, 필수 필드, 시각·원천 유효성을 검사한다. Choice confidence 임계값과 Noul 확률 임계값은 서로 다른 값으로 평가·설정한다.

산술·시간·중복·원문 해시 검사는 Python이 처리한다. 모델 출력을 주문 승인·실행 권한이나 사용자 동의로 취급하지 않는다.

## 6. 연동·장애·기록

- 기존 Python 서비스 안에 공급자와 무관한 판단 인터페이스를 두고 Jev 어댑터·규칙 기준선·가짜 응답을 교체한다. 별도 서버·에이전트 토론 시스템은 첫 범위에 포함하지 않는다.
- 초기 기능은 꺼진 상태로 배포한다. 개발자가 명시적으로 실험을 켰을 때만 호출한다. API 키는 Python 실행환경에서 관리하고 Godot·저장소·실험 로그에 넣지 않는다. 처음에는 공개 문서만 입력한다.
- 평가에는 사용 가능한 명시적 모델 버전을 고정하고 실제 응답 버전을 저장한다. 별칭만 제공되면 응답 버전 변화 전후를 구분하고 같은 실험 결과로 합치지 않는다.
- 캐시 키에 원문 해시, 실제 본문 범위, 질문·분류표·모델·정책 버전을 포함한다. 모델 갱신이나 원문 정정 시 기존 판단을 무효화하고 재평가 이력을 남긴다.
- 첫 실험은 요청 전체 5초 제한·총 2회 이하 시도를 제안값으로 둔다. 대기·재시도를 포함해 시간 예산을 지키고, 요청 크기·호출량·실험 비용 상한은 실행 전에 설정한다. 취소·종료 뒤 늦은 응답은 현재 화면에 적용하지 않는다.
- 공급자 장애·할당량·타임아웃은 `unavailable`, 형식·계약 오류는 `failed`로 기록한다. 이를 기타·정보부족이라는 성공 라벨로 바꾸지 않는다. 원래 기사 목록은 유지하고 분류 미완료를 표시한다.
- 낮은 확신은 검토 대기함으로 보낸다. 대체 LLM 경로는 별도 예산·정책이 있을 때만 쓰며 자동 무제한 호출을 하지 않는다. 재시도·대체 비용도 실험 지표에 포함한다.
- 로그는 원문 식별자·입력 및 결과 버전·상태를 연결한다. 모델 재호출은 달라질 수 있으므로 당시 저장된 입력·결과로 판단을 재생한다.
- 감시는 실패·보류·분류 분포·입력 길이·수동 정정률 변화를 관찰한다. 정답 없는 운영 중 높은 confidence만 보고 품질 정상으로 판정하지 않는다.

## 7. J3 화면 연결

기존 리서치 화면에 사건 분류, 검토 필요 상태, 원문·게시시각·분류 기준시각과 사용자 수정 기능을 붙인다. 별도 뉴스 앱을 만들지 않는다.

프톨레마이오스의 브리핑은 저장된 분류와 실제 원문을 사용한다. 원문이 없는 근거를 생성하지 않으며, 불확실한 결과를 확정 사실로 설명하지 않는다. 첫 화면에서는 확신을 정답 확률처럼 백분율로 표시하지 않는다.

Jev 호출은 비동기로 처리해 목록·사령부 조작을 막지 않는다. 장애 시 원문 열람·수동 분류가 가능해야 한다. 시범 적용 범위를 제한하고 기능을 끄면 기존 조회 흐름으로 복귀한다. 사용자 수정은 원래 결과를 지우지 않고 후속 평가 자료로 기록한다.

## 8. 후속 연구

### J4 · 정성 정보를 라니아케아 계열 모델 입력으로

문서에 수요 둔화, 가격 전가, 확정 계약, 차환 목적 등의 내용이 나타나는지 좁은 질문으로 평가한다. 질문값·불확실성·결측 여부를 특징 후보로 보존한다. 금액·기간의 정확한 계산은 원자료와 Python이 담당한다.

LLM의 질문 제안 → Jev의 문서 판단 → 기존 수치모형의 평가 구조를 연구한다. 공식 예제는 와인 평가 데이터를 사용하므로 금융 성능의 근거로 인용하지 않는다.

R1의 이용가능시점·모델 명세와 R2의 날짜 분할을 적용한다. 기업명·미래 지식·정정 문서·중복 사건에 의한 누출을 점검하고, 가격·재무만 쓰는 기준선에 비해 추가한 특징의 효과를 따로 비교한다. 질문 탐색과 최종 평가를 분리하며 이후 시점에서 주문 없는 관측을 쌓는다. 텍스트 분류가 정확하다는 이유만으로 비중을 바꾸지 않는다.

### J5 · 다른 적용처

| 후보 | 작은 적용 범위 | 유지할 경계 |
| --- | --- | --- |
| 헤파이스티온 요청 분류 | 조회·비교·설명·저장 요청·판단 불가를 구분해 기존 기능 후보로 연결 | 복합 명령·모호한 수량은 기존 대화 경로로 전달. 분류 결과가 사용자 승인이나 실제 변경을 대신하지 않음 |
| 참모 설명 보조 점검 | 원문과 결론의 과장, 실제 도구 결과 없이 완료했다고 주장하는지 검사 | 수치 대사는 Python. 두 AI의 일치를 독립적인 사실 검증으로 취급하지 않음 |
| 게임 NPC 행동 | 사건 발생 시 준비된 보고·정찰·집결 행동 후보 선택 | 매 프레임 원격 호출 금지. 경로 탐색·애니메이션·기본 행동은 게임 코드, 지연·장애 시 상태머신 사용 |

각 항목은 기존 방식의 구체적인 문제가 확인되면 별도 실험한다. JEV-01을 통과했다고 자동으로 채택하지 않는다.

## 9. 구현 시 검증할 사례와 인수인계

계획만 작성하는 이번 변경에서 아래 테스트를 새로 실행한 것은 아니다. J1 이후 구현의 완료 조건이다.

- 정상 응답, 필드 누락·모르는 라벨·비정상 확률·날짜, 모델 버전 불일치.
- 제목만으로 불충분한 입력, 혼합 사건, 부정문, 기업 동명이인, 원문 안의 모델 지시문.
- 같은 사건의 전재·후속 보도와 원문 정정, 판단시점 이후 이용가능 자료 차단.
- 낮은 confidence와 정보부족 라벨의 구분, 상충 답변의 검토 전환.
- 타임아웃·제한 응답·취소·재시작·늦게 도착한 결과, 비용 상한과 재시도 종료.
- 캐시 버전 변경, 같은 저장 결과의 재열기, 원문·Python·화면·참모 내용 일치.

다음 개발 작업은 **J0: 공개 한국어 뉴스·공시의 입력·라벨 계약과 비교 실험 명세**다. 이미 준비된 작은 표본으로 분류 경계부터 검토하고, J1은 기존 Python 실행 경로를 확인한 뒤 가짜 응답으로 계약을 먼저 검증한다. API를 사용할 수 없어도 데이터·계약 작업은 진행할 수 있다.
