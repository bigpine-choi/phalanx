# 기존 연구 코드 활용 로드맵

작성: 2026-09-30 KST  
상태: 개발계획에 편입한 작업 목록. 이 문서의 추가는 모델 이식·학습·성과 검증·실거래 구현 완료를 뜻하지 않는다.

## 1. 목적과 기존 계획에서의 위치

라니아케아의 데이터 처리·시계열 예측·혼합·배분 실험과 ETF·뉴스 프로젝트에서 유용한 설계를 계승한다. [통합 제품 비전](product-vision.md)의 M1 대화형 투자 흐름과 M2 데이터·추천 검증을 보완하며, [네 엔진 아키텍처](four-engine-architecture.md)의 공통 기반과 연구·검증 엔진부터 적용한다.

1인 개발 기준으로 기존 Python의 가격 이력·피처·선정·위험모형·ERC·NAV와 의사결정 기록을 우선 재사용한다. 새 시스템 전체를 병렬로 만들거나 기존 계산을 Godot에 복제하지 않는다. 학습 코드는 연구 영역에 두고, 제품은 버전이 고정된 결과와 명세를 받아 표시·비교한다. 긴 학습 작업을 앱 실행의 필수 조건으로 만들지 않는다.

## 3. 우선순위와 실행 항목

P0는 후속 모델 실험의 선행조건, P1은 기준선 확보 후 비교할 연구·화면 기능, P2는 후속 확장이다. 우선순위는 출시일이나 수익 실현 시점의 약속이 아니다.

### R1 · P0 — 시점별 데이터와 학습·추론 명세

**원본 근거:** v2.5 셀8 거시변수, 셀10·21 rolling Z-score, 셀13 데이터셋, 셀17 학습, 셀23 추론.

- 기존 가격 데이터에 관측시각·실제 이용가능시각·판단시각, 시장 시간대, 원천·정정 버전·스냅샷을 연결한다. 미국 시장 자료는 한국 판단시각 전에 이용 가능했던 값만 결합한다.
- 셀8의 선형 보간은 이후 관측값을 사용할 수 있으므로 연구 입력에 그대로 사용하지 않는다. 과거에 실제 관측된 값만 사용하는 정책, 최대 유효기간, 결측 표시를 명시한다.
- 당일을 포함한 rolling 계산은 그날 종가 확정 후 판단에서만 허용한다. 신호 생성시점과 거래 가정시점을 분리한다.
- 데이터·모델 명세에 특징 이름과 순서, ETF-ID, 수익률 종류·단위·기간, 전처리 버전, 학습 종료일, 데이터 해시, 코드·가중치 버전을 보존한다.
- 셀23처럼 현재 파일목록으로 ETF-ID를 다시 생성하지 않는다. 학습 때 저장한 매핑을 읽고 미등록 종목은 명시적으로 보류한다. 학습·추론 모델 정의를 하나로 통합한다.
- 분배금·기업행동·수정가격 처리의 중복 여부와 지원 범위를 기록한다. 총수익 자료가 없으면 가격수익 연구라고 표시하고 공식 NAV와 혼합하지 않는다.

ETF 저장소의 [분배금 수집 파일](https://github.com/bigpine-choi/ETF_Diversification/blob/7e4c58554fe98334ce44f082a30d4ffb56452b62/ETF_korean_etf_dividend_data_crawler.py)은 한 상품의 테이블을 출력하는 시제품이다. 완성된 이벤트 원장·총수익률 계산기로 취급하지 않고 위 입력요건의 참고로만 사용한다.

**완료 기준:** 미래 자료를 추가·변경해도 과거 판단시점의 입력은 변하지 않는다. 파일 순서 변경에도 ETF-ID가 동일하다. 잘못된 특징·버전·단위는 거절하고, 미래 Target 없는 최신 입력으로 추론할 수 있다.

### R2 · P0 — 공통 날짜 기반 비교·검증기

**원본 근거:** v2.5 셀17의 `SPLIT="time_by_etf"`, `PURGE_GAP=5`, `compute_train_std_by_etf()`.

- ETF별 데이터 비율에 따른 시간분할을 모든 종목이 공유하는 날짜 경계로 확장한다. 각 학습 표적의 관측 완료시각이 검증 시작 전에 끝나는지 검사한다.
- 1·3·5일 표적의 실제 기간 중첩을 기준으로 purge를 적용한다. 고정 5행을 모든 데이터의 충분조건으로 간주하지 않는다. 전처리·분산 추정·혼합 계수도 학습 구간에서만 적합한다.
- 기존 선정 규칙을 기준선으로 고정하고, 단순 선형 예측과 이후 R3 모델을 같은 입력·기간·거래 가정으로 비교한다.
- 순차 평가와 별도 최종 평가기간을 유지한다. 시도 횟수·실패 실험·설정 변경을 기록하고, 최종기간 결과를 보고 재조정하면 새로운 이후 관측으로 재검증한다.
- 시점별 유니버스와 상장·폐지 이력을 확보한다. 원본의 현재 생존 ETF만 소급 평가하면 그 선택 편향을 명시하고 일반화된 성과 근거로 사용하지 않는다.
- 예측 오차·순위 품질과 비용 차감 수익률·낙폭·회전율·집중도를 분리 보고한다. 선정 효과와 배분 효과는 한쪽을 고정해 비교한다.

**완료 기준:** 미래 특징·라벨·보정계수가 학습에 섞이지 않고 동일 입력·버전의 결과가 재현된다. 수수료·세금·슬리피지·거래량 제약과 미반영 항목이 드러난다. 채택 기준·최소 평가기간은 결과를 보기 전에 기록한다.

### R3 · P1 — 다기간 예측 모델을 교체 가능한 연구 후보로 등록

**원본 근거:** v2.5 셀17·23의 `FourierBlock`, `TimesBlock`, `MultiScaleTimesNet`, ETF embedding, 120·60·20일 분기와 1·3·5일 예측.

- 공통 예측 출력에 종목, 판단시각, 예측기간, 수익률 단위, 모델·데이터 버전, 상태를 포함한다. 예측값을 곧바로 목표비중이나 주문으로 취급하지 않는다.
- 기간별 분기, embedding, 복합 손실함수를 각각 제거·추가한 실험으로 기여를 확인한다. ETF 연구 결과를 국내 개별주식에 바로 일반화하지 않는다.
- 로그수익률·단순수익률 변환과 일·연 단위 환산을 일치시킨다. 모델 파일이 없거나 유효기간이 지났으면 계산 실패·보류 상태를 반환한다.
- 원본의 Colab 경로·설치 셀·전체 학습 실행을 제품 코드로 복사하지 않는다. 학습 시간·메모리·추론 지연도 채택 판단에 포함한다.

**완료 기준:** R2의 같은 조건에서 단순 기준모형과 비교할 수 있고, 모델 교체가 선정·배분·화면 코드를 다시 쓰게 하지 않는다. 개선이 확인되지 않으면 연구 후보로만 보존한다.

### R4 · P1 — 검증 근거가 있는 예측 혼합과 감시

**원본 근거:** v2.5 셀28의 `dynamic_black_litterman_blend_v2()`와 `ai_weights_log`.

- 원본의 예측 크기·불일치 기반 혼합은 휴리스틱 기준선으로 보존한다. 이름과 달리 Black–Litterman 사후분포 계산을 구현한 것으로 설명하지 않는다.
- 새 혼합안은 판단시점 전에 관측이 끝난 검증성과, 오차·불확실성, 표본수에 근거해 연구한다. 큰 예측값을 높은 적중 확률로 해석하지 않는다.
- 예측값, 반영비율, 반영 이유, 데이터 시점, 유효 상태를 의사결정 기록에 남긴다. Godot와 참모는 같은 계산 결과를 설명한다.
- 데이터 지연·모델 노후화·검증 성능 저하를 감시에 연결한다. 보류, 신규 의도 차단, 이미 검증된 기준 전략 사용 중 어떤 처리를 할지는 사전에 정책으로 정한다. 근거 없는 자동 전략 교체는 하지 않는다.

**완료 기준:** 판단 이후 실현수익률이 혼합비율에 섞이지 않는다. 혼합안은 고정 비중 혼합·AI 미사용 기준선과 비교되고, 화면의 반영비율과 저장 결과가 일치한다.

### R5 · P1/P2 — 배분안 비교 화면과 기대수익 기반 배분 연구

**원본 근거:** ETF_Diversification의 EWMA·효율적 투자선·비중표, v2.5 셀28의 `ewma_cov_matrix()`, `project_long_only_with_caps()`, SLSQP 최대 샤프와 inverse-vol fallback.

- **P1:** 기존 연구 경로의 균등·역변동성과 제품 연결된 ERC를 같은 종목·시점·위험모형·제약으로 비교하는 결과 계약과 사령부 화면을 만든다. 세 방식이 모두 동일한 제품 흐름에 연결됐다는 뜻은 아니다. 지원하지 않는 제약은 적용했다고 표시하지 않는다.
- 비중, 위험·위험기여, 집중도, 현금, 예상 회전율과 비용을 비교하고 아리스토텔레스가 차이를 설명한다. 추정치와 실현성과를 구분한다.
- **P2:** R2 검증기와 유효한 예측 입력이 준비되면 최소분산·기대수익 기반 배분을 별도 후보로 추가한다. 종목·그룹 상한과 거래비용을 반영하고 기존 ERC와 비교한다.
- ETF_Diversification의 50만 회 랜덤 탐색을 매번 UI에서 돌리는 구조는 계승하지 않는다. 시각화용 표본 수·난수 시드·응답시간을 제한하고 계산은 화면 밖에서 처리한다.
- v2.5의 횡단면 Z-score·`tanh`로 압축한 `mu_vec`는 점수 성격의 입력이다. 이를 보정된 실제 기대수익률이나 달성 가능한 샤프로 표시하지 않는다.
- 최적화 실패·예측 누락·불가능한 제약을 명시한다. 대체 계산을 하면 그 이유를 기록하고, 제약을 만족하지 못한 결과를 성공으로 반환하지 않는다.

**완료 기준:** 선정 신호를 고정한 배분 비교가 가능하다. 비중합·상한·현금 조건, 실패·취소·재시작·저장과 재열기가 일관되고, Python·화면·참모의 수치가 동일하다.

### R6 · P2 — 뉴스 정찰 데이터와 근거 표시

후속 구체화: [Jev 활용 개발계획](jev-integration-plan.md)의 JEV-01에서 한국어 뉴스·공시 분류를 규칙·기존 LLM·Jev로 비교한다. 고정 자료를 사용한 작은 실험은 R1·R2와 병행할 수 있으며, 뉴스 화면 연결은 분류 품질·비용·지연 기준을 통과한 뒤 진행한다. 모델 채택과 R6 전체 구현은 미완료다.

**원본 근거:** `naver_news_crawler_worldcloud.py`의 `fetch_news()`, `get_last_page()`, `get_news_titles_by_date()`와 `create_wordcloud()`.

- 수집 아이디어를 프톨레마이오스의 정보 수집 어댑터로 확장한다. 기사 URL·언론사·게시시각·수집시각·수정 여부와 수집 실패를 보존한다.
- 제목·내용의 중복, 재배포, 종목·기업명 연결을 처리한 뒤 뉴스 주제의 변화를 표시한다. 형태소 빈도는 관심 주제 탐색에 사용한다.
- 현재 제목 문자열 중심의 반환 형식을 확장하고, 페이지 누락·수집 실패·기사 없음과 재개 위치를 구분한다. 상위 빈도 단어 자동 제거·특정 키워드 예외 처리도 고정 규칙으로 계승하지 않고 원문 대비 왜곡을 점검한다.
- 크롤링 셀을 그대로 운용하기보다 허용된 수집 경로·이용 범위를 확인하고 기존 리서치 경로와 통합한다. 과거 뉴스만 재해석한 LLM 결과를 실전 투자성과로 제시하지 않는다.

**완료 기준:** 브리핑의 각 주장을 원문과 당시 이용가능시점으로 추적할 수 있다. 중복 수집과 실패가 구별되며 뉴스 빈도가 자동 매수 명령이 되지 않는다.

## 4. 첫 구현 묶음과 후속 순서

첫 구현 묶음은 **R1의 데이터 명세 + R2의 단순 기준전략 비교**다. 고정된 작은 데이터 스냅샷과 한 기준전략으로 입력 → 판단 → 비교 보고서 → 저장·재실행을 먼저 연결한다. 기존 M1 화면 개발은 이어간다.

1. R1과 R2로 데이터 시점·단위·버전·검증 계약을 고정한다.
2. R5의 기존 배분안 비교를 먼저 연결하고, R3의 예측 모델 한 개를 연구 후보로 추가한다.
3. R4의 혼합을 비교한 뒤 R5의 기대수익 기반 배분을 검증한다. 예측의 효과와 배분의 효과를 따로 측정한다.
4. 통과한 후보만 네 엔진의 **주문 없는 운용 → 감시 → 성과 재평가**에 연결한다.
5. R6는 기존 리서치 화면·근거 저장 체계가 준비된 범위에서 후속으로 진행한다.

검증 탈락 모델은 기록만 보존하고 기존 기준전략을 유지한다. 새 모델 채택, 정책 변경, 실거래 연결·활성화는 별도 단계다. 이번 작업에서는 원본을 실행·학습하지 않았고 투자성과를 검증하지 않았다.
