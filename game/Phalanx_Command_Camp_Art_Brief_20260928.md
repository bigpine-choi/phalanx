# Phalanx · 쿼터뷰 야영지와 고정시점 사령부 제작 지침

2026-09-28 사용자 설계 정정을 반영한 현재 기준이다. 이 문서의 목표·검수 기준을 구현 완료나 검증 PASS로 해석하지 않는다. 실제 결과는 [현재 검증 기록](docs/QUARTER_VIEW_VALIDATION.md)에 별도로 남긴다.

## 1. 설계와 범위

기본 게임은 **쿼터뷰 야영지**, 사령부에 입장하면 **고정시점 내부**다. 3D 제작 부담을 줄이고 화면에 보이는 구역의 품질을 높이기 위한 의도적인 설계다. 과거 ‘사령부 1인칭 자유 이동 유지’, 근접 E, 마우스 캡처, 모든 소품의 뒷면까지 입체 제작 요구는 현재 요청에 적용하지 않는다.

이번 범위는 사령부 주변의 작은 이동 구역, 입출입, 고정 내부의 테이블 클릭, 기존 투자 대시보드 왕복이다. 큰 맵·전투·훈련·복잡한 NPC 대화·신규 투자 기능으로 확대하지 않는다. 기존 대시보드, 차트, 팝업과 가상 데이터 표시는 유지한다. 실제 계좌와 Python 투자엔진은 연결하지 않는다.

## 3. 사용자 흐름과 입력

1. 시작은 정해진 높은 사선 구도의 야영지다. 왼쪽 클릭으로 이동 목적지를 지정한다. 건물·장애물·이동 가능 구역이 화면의 실제 배치와 대응해야 한다. 자유 카메라 회전은 없다.
2. 사령부 입구를 식별하기 쉽도록 만들고, 접근 후 상호작용으로 내부로 전환한다.
3. 내부는 한 고정 구도다. 보행·시선 회전·마우스 캡처·중앙 조준점 없이 지도나 테이블에 직접 호버·클릭한다. 선택 가능 영역에 시각 피드백을 제공한다.
4. 대시보드를 닫으면 같은 사령부 구도로 돌아온다. 별도의 명확한 ‘야영지로’ 조작으로 외부에 나가며 캐릭터를 안전한 입구 부근에 복원한다.
5. 팝업이 열린 상태의 Esc는 팝업부터 닫는다. 다음 Esc로 대시보드를 닫으며 같은 입력이 장면 복귀까지 연쇄 처리되지 않도록 한다. UI 뒤쪽 장면은 입력을 받지 않는다.

## 4. 미술 제작

### 야영지

사령부 주변의 작은 이동 구역을 먼저 완성한다. 붉은 군막과 따뜻한 햇빛, 식생·흙길·수레·항아리·군기 등의 공간 밀도가 기준이다. 화면 전체에 같은 소품을 반복하기보다 입구와 이동 동선을 읽을 수 있는 여백을 둔다. 캐릭터의 크기·방향·그림자를 배경에 맞추고, 건물 앞뒤로 이동할 때 가림 규칙이 뒤집히지 않게 한다.

### 고정 사령부

지도는 화면의 중심이며 상판 앞면이나 다리가 구도를 과점유하지 않는다. 깊은 내부 그림자와 입구의 따뜻한 역광을 대비시키되 지도와 주요 소품은 읽을 수 있어야 한다. 처진 천과 장식·큰 주름, 낡은 목재의 결·마모, 황동/청동의 국소적인 하이라이트를 구분한다. 문서·잔·투구·무기·두루마리는 비대칭으로 놓아 사용 중인 공간을 만든다. 과도한 광택·블룸·전면 색 필터는 피한다.

불꽃·깃발 등 제한된 요소만 움직여 생동감을 준다. 정지 배경에 붙인 효과가 광원·위치·크기 면에서 어긋나지 않아야 한다. 움직임을 많이 추가하는 것이 품질 기준은 아니다.

### 표현 방법과 에셋

고정 카메라 3D, 사전 렌더 배경, 깊이를 나눈 2.5D 요소를 필요에 맞게 혼합할 수 있다. 이미지를 사용할 경우 종횡비를 보존하고 배경·클릭 다각형·캐릭터·가림 요소에 같은 화면 좌표 변환을 적용한다. 16:9와 3:2 창 크기에서 늘어짐, 과도한 잘림, 클릭 어긋남을 확인한다. 배경 확대 해상도와 움직이는 요소의 표현 차이도 평가한다.

이미지 생성 도구는 배경/시각 에셋 제작에 사용할 수 있다. 실제 사용한 파일, 생성 도구와 사용한 참조 범위를 기록하며 생성 이미지를 손수 제작한 3D 모델이나 역사 고증 자료로 보고하지 않는다. 외부 다운로드 에셋은 출처·라이선스·사용 조건을 확인하고 프로젝트에 기록한다. 확보하지 않은 후보를 사용했다고 주장하지 않는다. 유료 구매·계정 생성·새 프로그램 설치가 필요하면 해당 항목만 별도로 알리고 독립적으로 가능한 작업을 계속한다.

### 분석 화면

차트·표·수치·검색·모의 계획은 실제 UI로 유지한다. 시안의 예시 가격·비중을 실제 투자값으로 취급하지 않는다. 짙은 배경, 읽기 쉬운 한글, 절제된 청동색 테두리와 성과 색상으로 사령부 분위기를 잇되 정보 가독성을 우선한다. 모든 가격·계좌·계획이 가상 데이터라는 표시는 지우지 않는다.

## 5. 코드 책임

화면 전환, 야영지 이동/경로, 캐릭터, 사령부 클릭 상호작용, UI, 미술 구성을 분리한다. 기존 1인칭 관련 코드는 이전 작업으로 보존하되 새 기본 흐름에서 분리한다. 하나의 스크립트에 화면·이동·UI·데이터 기능을 모두 넣지 않는다.

현재 파일 연결은 [README 구조 표](README.md#구성과-제작-기준)를 따른다. 미커밋 아트 패스 B 작업을 보존하며 commit·merge·push·강제 초기화는 하지 않는다.

## 6. 검증과 완료 기준

기능과 미술은 별도로 보고한다. 과거 1인칭 테스트의 PASS를 새 구조의 검증으로 대신하지 않는다.

- 파싱 오류, 변경 파일 형식 오류를 검사한다.
- 새 흐름에 맞는 테스트로 경로·장애물·입구·테이블 호버/클릭·입력 차단·화면 상태·팝업 우선 Esc를 검사한다.
- 실제 Godot 창에서 이동 → 사령부 입장 → 테이블 클릭 → 대시보드 → 사령부 복귀 → 야영지 복귀를 조작한다.
- 1280×720과 1440×960에서 구도, UI 가독성, 클릭 영역 정렬과 대시보드 기능을 확인한다.
- 시작 야영지, 고정 사령부, 분석 화면의 스크린샷을 남긴다. 동일 조건 비교가 가능한 경우 비교 조건을 적는다.
- 자동/합성 입력, 컴퓨터 도구의 운영체제 창 조작, 사람이 직접 조작한 결과를 분리한다. 확인하지 못한 항목은 미검증으로 기록한다.
- 재질·천 주름·소품 밀도·접지·가림·제한된 움직임 등 시안 대비 개선과 남은 차이를 실제 화면을 근거로 설명한다. 단순 도형의 소폭 조정이나 기능 테스트 통과를 미술 목표 달성으로 바꾸어 말하지 않는다.
