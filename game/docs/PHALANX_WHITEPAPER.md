# Phalanx 공식 백서 · v1

기준일: 2026-09-30

이 문서는 팔랑크스의 목적, 현재 기능, 데이터 출처와 연결 범위를 설명하는 대표 문서다. 실행 방법은 [README](../README.md), 현재 우선순위와 여러 작업자의 통합 기준은 [개발 계획](../../docs/development-plan.md), 변경 이력과 검증 근거는 [세션 인수인계](SESSION_HANDOFF.md)를 따른다. 구현·검증·후속 계획을 구분하며, 외부 서비스가 제공하는 기능을 팔랑크스의 구현 완료 범위로 간주하지 않는다.

## 1. 목적과 사용 흐름

팔랑크스는 종목 탐색, 관찰 기록, 리서치와 포트폴리오 모의 계획을 하나의 투자 워크스페이스로 연결한다. Windows Godot의 야영지에서 사령부로 들어가 작전 지도를 열고, 시장·포트폴리오·리서치 화면을 사용한다.

대표 흐름은 **종목 검색 → 관심 등록·그룹 분류 → 차트·리서치 확인 → 노트 작성 → 선택적 참모 요청 → 모의 계획과 명령서 기록**이다. 종목 선택이나 그룹 편입 자체가 유료 AI 요청을 실행하지 않는다. 매매 계획은 사용자의 판단을 기록하는 모의 계산이며 실제 주문을 전송하지 않는다.

## 2. 현재 기능과 저장 원칙

- **시장 전체 검색:** 기존 Python discovery의 저장 종목 마스터를 재사용한다. 투자 후보 적격 여부와 검색 노출을 분리하고 ETF·우선주를 포함한다. 검색 입력마다 네트워크를 호출하지 않으며, 명시적 목록 갱신이 실패하면 이전 정상 목록과 수집 시각을 유지한다.
- **관심그룹·종목표:** 전체 관심·보유·사용자 그룹으로 종목을 관리한다. 그룹은 이름과 독립된 ID를 가지며 한 종목이 여러 그룹에 속할 수 있다. 여섯 열의 정렬과 표 재구성 뒤에도 선택을 종목코드로 연결한다.
- **사용자 기록:** 그룹 삭제나 그룹에서의 제거는 관심종목·노트를 삭제하지 않는다. 저장 v3는 v1/v2 자료를 메모리에서 이전하고 첫 정상 저장 때 원본 바이트를 백업한다. 빈 관심목록, 명령서·일지와 기존 필드를 보존한다.
- **리서치·참모:** 선택한 종목의 차트와 자료 출처·시점, 종목별 노트를 연결한다. 참모 분석은 명시적 요청으로 실행하며 계산 결과와 해석을 구분한다.
- **포트폴리오:** 관측한 보유종목을 바탕으로 비중·수량·현금 가정을 비교하고 명령서에 기록한다. 미보유 종목의 배분 편입은 후속 범위다.

세부 검증은 [시장 검색 기록](MARKET_CATALOG_SEARCH_VALIDATION.md), [관심그룹·종목표 기록](WATCHLIST_GROUPS_TABLE_VALIDATION.md), [포트폴리오 안내](PORTFOLIO_SIMULATOR.md)를 참고한다.

## 3. 데이터 출처와 시점

| 자료 | 출처·연결 | 시점과 표시 원칙 |
| --- | --- | --- |
| 검색용 종목 목록 | WSL의 Python discovery → 저장 목록 | 출처와 수집 시각 표시. 목록은 현재가가 아니다. |
| 단일종목 일봉 | 기존 WSL Python → 한국투자증권 KIS | 전일까지의 수정주가 일봉. 마지막 종가와 기준일을 표시한다. |
| 잔고·계좌 관측 | 기존 WSL Python → 한국투자증권 KIS | 잔고 조회 시점의 값. 일봉 종가와 출처·시점을 구분한다. |
| NH PLUG 현재가 | WSL Python SDK → NH투자증권 KRX 현재가 | 아래 4장의 별도 조회 기능. 연결 프로그램이 응답을 받은 시각을 표시한다. 거래소 체결 시각은 아니다. |
| 관심·그룹·노트·명령서·일지 | 기존 로컬 workspace 저장 | 사용자 기록이다. 시세 캐시 및 계좌 관측과 별도로 보존한다. |

검색 가능 범위와 각 조회 경로의 지원 코드 범위는 다르다. 미지원·미조회·조회 실패를 구분하며 자료가 없는 값을 임의로 채우지 않는다. 서로 다른 출처와 기준 시각의 가격을 같은 관측값으로 합치지 않는다. 관심그룹 종목표에는 가격 열을 두지 않았다.

## 4. NH PLUG 연결

### 도입 목적과 현재 구현

NH PLUG는 한국투자증권 일봉과 구별되는 두 번째 시세 출처로 추가했다. **현재 구현 범위는 리서치 화면의 `NH 현재가` 버튼을 통한 국내주식 KRX 현재가 조회**다. 자동 스트리밍, NH 계좌 조회, 주문·체결, NH 일봉 병합은 포함하지 않는다.

NH투자증권 공식 Python SDK는 `nhplug` 패키지와 URI 경로 방식의 호출을 제공한다. 팔랑크스의 연결 프로그램은 `currentPrice` 경로에 종목코드와 KRX 시장을 전달한다. 외부 SDK의 전체 기능 범위와 팔랑크스에서 연결한 범위는 구분한다. [NH투자증권 공식 SDK](https://github.com/PLUG-OpenAPI/nhplug-sdk)

| 항목 | 구현 계약 |
| --- | --- |
| 사용자 조작 | 선택 종목의 리서치 화면에서 `NH 현재가`를 명시적으로 요청 |
| 지원 입력 | 숫자 6자리 국내 종목코드 |
| 호출 | `/krstock/quote/v1/currentPrice`, `iem_cd`, `market_cd=KRX` |
| 결과 | `Output_0.stck_prpr`에서 검증한 양의 원화 정수 현재가 |
| 화면 표시 | NH투자증권·KRX 출처와 연결 프로그램의 응답 완료 시각. 거래소 체결 시각은 알 수 없으므로 표시하지 않음 |
| 비동기 연결 | 요청 ID·종목코드·세대 번호로 응답을 연결하고, 종목 변경 뒤 도착한 이전 응답은 표시하지 않음 |
| 형식 검사 | 제공자·통화·시장·코드·가격 범위 검사, 관측 시각이 현재보다 5분을 초과해 과거이거나 1분을 초과해 미래이면 거부 |
| 실패 처리 | SDK 없음·설정 확인·조회 실패를 구분. KIS 일봉·계좌 값·모의 계획을 NH 값으로 덮어쓰지 않음 |

연결 경로는 **Godot → WSL Python 연결 프로그램 → `nhplug` SDK → NH PLUG → 검증된 결과 → 별도 현재가 표시**다. discovery의 POSIX 저장소나 인증 처리를 Windows SQLite 실행으로 옮기지 않는다.

### 인증정보와 결과의 경계

NH 앱키·앱시크릿은 WSL 쪽 SDK 설정에서 읽는다. Godot 화면이나 workspace 프로필에 키를 입력·복사하지 않으며, 연결 프로그램은 결과 봉투에 키·토큰·원문 예외를 쓰지 않는다. 저장소에는 실제 인증정보를 포함하지 않는다. 설정 파일의 탐색 방식과 운영 환경별 설정은 [공식 SDK 설정 안내](https://github.com/PLUG-OpenAPI/nhplug-sdk#설정--파일-하나만-관리하면-됩니다)를 따른다.

### 구현 상태와 남은 확인

NH 현재가 기능은 게임 브랜치의 PR #30으로 합쳐졌고, 이 통합본에서는 Python 엔진과 같은 저장소의 `game/`에 둔다. 사용자가 WSL의 `~/.nhplug/.env`에 키를 저장한 뒤 공식 SDK의 실제 `currentPrice` 호출과 Windows 게임 연결 경로의 응답을 확인했다. 게임 모델·화면의 자동 검사는 합성 응답으로 수행했으며, 키·토큰·계좌 원문은 테스트나 저장소에 넣지 않았다. 인증 설정은 [NH 연결 안내](NHPLUG_READONLY.md)를 따른다.

`fetched_at`은 SDK 응답을 받은 뒤 기록하고 화면에는 ‘조회 완료’로 표시한다. 이것은 API 요청을 마친 시각이며 시세의 체결·갱신 시각 보증이 아니다. 실제 게임 창에서 버튼 조작, 네트워크 장애 후 복구, 종목 전환과 가독성은 별도로 계속 확인할 항목이다.

## 5. 검증과 확장 기준

관심그룹·종목표는 격리된 저장본에서 그룹 편집·다중 편입·삭제 시 노트 보존, 저장 이전·원본 백업, 별도 프로세스 복원을 검증했다. 실제 1280×720과 1440×960 창에서 표·스크롤·선택을 확인했다. 최종 검토에서 비동기 갱신이 새 선택을 덮는 경합을 수정하고 해당 검사와 관련 UI 57건을 다시 통과했다. 자세한 범위와 기존 319건 작업 트리 검증의 포함·제외 사항은 [검증 기록](WATCHLIST_GROUPS_TABLE_VALIDATION.md)에 남겼다.

향후 NH와 KIS 자료를 비교할 때에는 종목 식별자, 시장, 관측 시각과 가격 기준부터 맞춘다. 현재가와 수정주가 일봉, 잔고 조회가를 자동으로 대체하거나 혼합하지 않는다. NH 일봉·실시간 구독·계좌·주문 연결은 각각 새로운 범위와 검증을 갖는 별도 작업으로 다룬다.
