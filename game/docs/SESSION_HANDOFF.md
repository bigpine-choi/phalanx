이 문서의 아래 항목은 작성 당시의 작업 기록이다. 현재 구조와 다음 순서는 [개발 계획](../../docs/development-plan.md) 및 [공식 백서](PHALANX_WHITEPAPER.md)를 우선한다. Python 엔진은 저장소 루트, Godot 게임은 `game/`에 둔다. 게임 기능은 시장 전체 검색, 관심그룹·종목표, NH 현재가 연결의 **커밋된** 변경을 통합했다. 다른 작업 복사본의 미커밋 변경은 이 통합본에 포함하지 않았다.

## 공식 백서와 NH PLUG 범위 · 2026-09-30

사용자 요청으로 [PHALANX_WHITEPAPER.md](PHALANX_WHITEPAPER.md)를 대표 백서로 만들었다. 현재 기능·저장 원칙·출처별 데이터 시점을 정리하고 NH PLUG의 별도 KRX 현재가 조회, WSL SDK 인증 경계, 비동기 응답 연결과 남은 실환경 검증을 명시했다. NH 코드는 로컬 추가 작업으로 보존하며 관심그룹 기능 커밋에 포함하지 않았다. 백서 문서화는 NH 기능의 배포·실제 API 검증 완료를 뜻하지 않는다.

NH 코드 검토에서 `fetched_at`은 SDK 호출 직전의 관측 시각임을 확인했다. 현재 UI의 ‘수신’ 표기와 의미를 맞추는 일은 NH 후속 작업으로 남겼으며, 백서에는 응답 완료·거래소 체결 시각과 구분해 적었다. 백서의 로컬 링크와 diff 형식을 확인했고, 문서 추가로 기능 검사를 반복하지 않았다.

관심그룹 기능은 `5e8d3c02016278ca69619fc97b9935f5116c7212`로 `origin/feature/watchlist-groups-table-v1`에 일반 푸시했고 원격 해시 일치를 확인했다. 지정 커밋 메시지는 `feat: add watchlist groups and sortable table`이다. 추가 백서·README 링크·이 인수인계만 후속 문서 커밋으로 보존한다.

## 최신 변경 · 관심그룹과 종목표 v1 · 2026-09-30

`bf032ef` 기반 `feature/watchlist-groups-table-v1`에서 구현했다. 시작 시 남아 있던 참모의 늦은 완료 콜백 수정과 회귀 2건(`advisor_panel.gd`, `market_catalog_ui_test.gd`)은 이번 기능 커밋에서 제외하고 작업 트리의 미커밋 변경으로 보존한다.

시장 왼쪽 **관심그룹 · 종목표**에서 전체 관심·보유·사용자 그룹을 전환하고, 그룹 생성·이름 변경·삭제·다중 그룹 편입을 지원한다. 그룹 이름과 독립된 ID를 사용한다. 그룹 편입은 전체 관심에도 추가하고, 그룹에서 제거하거나 그룹을 삭제해도 관심과 노트는 유지한다. 전체 관심 해제 시 그룹 참조를 정리하며 노트는 보존한다.

종목표는 이름·코드·시장·종류·보유 여부·조회 상태 6개 열을 양방향 정렬하며 선택은 코드 기준으로 유지한다. 가격 열은 없고 확인하지 못한 메타데이터는 `—`다. 표 선택은 기존 차트·리서치·참모 대상을 연결하고 유료 AI를 자동 실행하지 않는다. 그룹 모델·표 UI·표 행 구성은 별도 모듈, 사령부는 기존 기능과의 연결을 맡는다.

저장 v3의 `watchlist_view`에 그룹·선택 그룹·정렬을 보관한다. v1/v2는 메모리에서 이전하고 첫 저장 때 원본을 백업하며 빈 관심목록·노트·종목명·명령서·일지·알 수 없는 필드를 보존한다. 임시 카탈로그 A를 다시 선택한 뒤 B로 이동할 때 A가 남던 표시도 수정했다.

검증 결과·실제 창 확인·직접 확인 순서·남은 범위는 [WATCHLIST_GROUPS_TABLE_VALIDATION.md](WATCHLIST_GROUPS_TABLE_VALIDATION.md)를 기준으로 한다. 테스트는 격리된 저장본과 오프라인 합성 자료를 사용한다.

구현 완료 당시 작업 트리에서 모델/이전 46건, 표 스트레스 91건, 그룹 UI 57건, 기존 저장 45건, 작전 39건, 카탈로그 UI 41건이 통과했다. 합계 319건에는 이번 커밋에서 제외한 기존 참모 수정과 추가 회귀 2건이 포함되며, 커밋에 담기는 카탈로그 UI 테스트는 기존 39건이다. 별도 프로세스 write/read로 그룹·정렬·노트·작전 복원을 확인했고, 실제 1280×720·1440×960 창에서 행 선택·정렬·스크롤·Esc와 그룹/노트 재실행 복원을 확인했다. 실제 마우스 선택 중 Tree 재진입 오류를 발견해 선택 전달을 지연 처리하고 두 해상도에서 오류 없는 로그로 재검수했다. 실제 API·계좌·유료 AI 재호출은 이번 변경의 검증 범위 밖이다.

최종 검토에서는 클릭 직후 이전 종목의 비동기 응답이 새 선택을 덮는 경합을 수정했다. 대기 선택 코드를 별도로 유지하고 최신 클릭만 전달한다. 참모 추가 수정과 NH PLUG 변경을 제외한 커밋 대상 사본에서 선택 경합 전용 검사와 그룹 UI 57건을 다시 통과했다. 기존 319건 전체는 반복하지 않았다. 저장 이전·백업·그룹 삭제 경로는 읽기 검토에서 추가 결함이 없었다. 커밋 메시지는 `feat: add watchlist groups and sortable table`, 원격은 다시 확인한 기존 비공개 `bigpine-choi/phalanx`이며 해당 기능 브랜치만 일반 푸시한다. 검토 중 추가된 NH PLUG 코드는 이 커밋의 범위 밖이다.

## 최신 변경 · 시장 전체 종목 검색 v1 · 2026-09-30

게임 기준 `fdc4d48`에서 `feature/market-catalog-search-v1`을 준비했다. 기존 discovery `view()`와 `list_candidates(view, status=None)`를 WSL Python 브리지로 연결하며, 검색 모델·비동기 연결·검색 창을 별도 파일로 분리했다. ETF·우선주와 투자 후보 제외 항목도 검색한다. 검색 입력은 저장 목록만 조회하고, 네트워크 수집은 명시적 목록 갱신에서 실행한다.

검색 결과는 최대 30개 버튼으로 표시한다. 코드·이름·시장·종류·출처·수집 시각과 무자료·결과 없음·실패 상태를 구분하며 식별자 충돌은 등록을 막는다. 관심·종목명·노트는 기존 workspace 저장 계약을 사용한다. 관심 해제 후 노트, 기존 프로필·명령서·작전 일지를 보존한다. 선택 종목은 기존 단일종목 일봉·리서치·참모로 이어지며 자동 유료 AI 요청은 없다. 미보유 종목의 배분 편입은 후속 범위다.

실제 F5 게임에서 discovery 목록 갱신을 한 번 실행했다. KOSPI 2,578개 + KOSDAQ 1,827개 = 4,405개, 두 시장 다운로드·파싱 성공, 이슈·식별자 충돌 0건. 완료 시각은 `2026-09-30T12:18:10.340890+00:00`(21:18:10 KST)이며 WSL 저장소·게임 캐시·화면 표시가 일치한다. 검증의 프로필·목록·일봉 캐시는 격리했고 실제 계좌 조회는 껐다.

구현 파일·수정 결함·검증 결과·재실행·미검증 항목·직접 확인 순서는 [MARKET_CATALOG_SEARCH_VALIDATION.md](MARKET_CATALOG_SEARCH_VALIDATION.md)를 기준으로 한다. 이전의 전체 검색 미구현 기록은 당시 상태다.

사용자가 마무리 변경의 커밋·푸시를 승인했다. `origin`은 기존 비공개 `bigpine-choi/phalanx`임을 GitHub 저장소 메타데이터로 확인했다. 작업 브랜치만 일반 푸시하며 Python `main`과의 병합이나 강제 푸시는 하지 않는다. 인증정보·사용자 프로필·실제 계좌 자료·캐시·검증용 임시 저장본은 저장소에 포함하지 않는다.

## 최신 변경 · 실계좌 시장 화면 · 2026-09-29 밤

시장에 전체 보유종목과 관심종목을 합친 목록, 실제 일봉·등락률·거래량·수신 시각, 계좌 요약, 선택 종목의 수량·평가액·증권사 손익·주식 내 비중을 연결했다. 예시 지수와 가격 생성은 런타임에서 제거했다. 아래 과거 기록의 ‘시장 예시’와 ‘리서치 5종목 제한’은 더 이상 현재 동작이 아니다.

시장과 리서치는 `research_view.gateway` 하나, 시장과 포트폴리오는 `simulator.account` 하나를 공유한다. 관심 등록한 신규 종목의 이름만 `security_names`에 저장하고 원본 잔고를 프로필에 추가하지 않는다. 선택한 보유종목의 비중 입력으로 이동하되 목표값을 바꾸지 않는다. 참모 이동은 API를 호출하지 않으며 실제 요청은 기존 버튼에서 한다. Python 일봉/참모 어댑터는 6자리 대문자·숫자 종목코드를 검증하고 기존 Phalanx 서비스를 재사용한다. 백엔드 원본은 수정하지 않았다.

사용법·검증·제한: [LIVE_MARKET_WORKSPACE.md](LIVE_MARKET_WORKSPACE.md). 사용자가 이번 변경의 커밋·푸시를 요청했다. 직전 GitHub 체크포인트 `a6fee96` 이후의 샘플 계좌 제거와 실계좌 시장 연결, 관련 테스트·문서를 `feature/camp-art-pass-b` 브랜치의 같은 체크포인트로 보관한다. 인증정보·사용자 저장본·실제 잔고·계좌 화면 캡처는 포함하지 않는다.

## 이전 변경 · 샘플 계좌 제거

사용자 요청으로 샘플 계좌 버튼·별도 화면, 시장의 가상 계좌 요약·보유량·비중 계획과 샘플 명령서 작성 경로를 제거했다. 계좌 계산과 새 기록은 실제 KIS 조회 기반만 허용한다. `market_data.gd`에는 시장 예시 가격·차트와 형식화만 남기고 가상 현금·보유량은 제거했다. 합성 계좌는 격리된 테스트 파일에서만 사용한다.

기존 v1/v2 프로필과 이미 봉인한 과거 일지는 읽을 수 있다. 새 프로필에는 샘플 계좌 필드를 만들지 않고, 기존 저장본의 알 수 없는 필드와 과거 초안/기록은 손상시키지 않는다. 리서치 참모는 적용된 실계좌 계획의 종목명·코드·목표 비중을 읽는다. 이전 단계의 샘플 계좌 사용 안내는 현재 동작이 아니다.

## 그늘 반응 후속 작업

`camp_light_field.gd`는 기존 배경의 6개 주요 그늘 구역을 원본 이미지 좌표로 관리한다. `quarter_camp`가 이 필드를 아바타에 주입하고, 이동 후 발 위치를 샘플링해 `commander_visual`의 실제 직사광·주변광·2D 드리운 그림자를 갱신한다. 부드러운 공간 경계와 짧은 시간 응답을 사용하며 초기화/위치 복원/복귀는 즉시 맞춘다. 발밑 접촉 그림자는 그늘에서도 남긴다. 태양광과 드리운 그림자 방향도 배경에 맞췄다.

최신 기록은 [CAMP_LIGHTING_VALIDATION.md](CAMP_LIGHTING_VALIDATION.md)다. 새 조명 검사 15(headless)/18(GPU), 보행 50, 흐름 157(headless)/162(GPU), 대시보드 PASS. 이번 GPU 흐름 검사는 캡처 저장 옵션이 없어 과거 174개와 수가 다르다. 두 해상도 OS 창의 정상 속도 전체 왕복, 팝업 우선 Esc, 야영지 위치 복원을 확인했다. 이동 중 재지정/Alt+Tab 정지는 도구 입력 간격 때문에 검수용 0.25배에서 확인하고 1배로 복구했다. 정상 속도 이동 중 Alt+Tab·사람 플레이는 미검증이다.

캐릭터 전체의 조명을 발 주변의 그늘 비율로 바꾸는 근사다. 작은 잎 그림자의 신체별 투영이나 동적인 배경 그림자는 없다. 망토의 태양 문양/옷단은 변형 UV를 따라 움직인다. 새 에셋 생성·다운로드 없이 기존 코드 재질을 보완했으며 시안의 인물 품질에 도달한 것은 아니다.

## 검증 상태와 다음 세션

현재 캐릭터의 실행 결과, 영상·연속 프레임, 변경 파일 및 남은 한계는 [AVATAR_MOTION_VALIDATION.md](AVATAR_MOTION_VALIDATION.md)를 기준으로 확인한다. [QUARTER_VIEW_VALIDATION.md](QUARTER_VIEW_VALIDATION.md)는 이전 단일 포즈 캐릭터 단계의 당시 기록으로 보존한다. 이 인수인계의 설명 자체는 테스트 PASS나 미술 완료를 뜻하지 않는다. 실제 테스트·GUI 증거가 없는 항목은 미검증으로 남긴다.

검증은 다음 세 층을 분리한다.

1. 자동/합성 입력: 파싱, 새 화면 전환, 경로/장애물, UI 입력 차단, 대시보드 상태 보존, 팝업 우선 Esc.
2. 컴퓨터 사용 도구의 실제 OS 창 조작: 클릭 이동부터 야영지 복귀까지 전체 왕복과 1280×720/1440×960 렌더·클릭 정렬.
3. 사람의 직접 조작: 사용자가 결과를 전달한 항목만 기록. 자동 도구 조작을 사람 검증으로 표기하지 않는다.

미술 평가는 테스트와 별도다. 시안 대비 재질·빛·밀도·캐릭터 접지·가림·애니메이션 한계를 실제 화면에서 설명한다. 단순 도형/균일 재질의 소폭 조정이나 테스트 통과만으로 시안 품질을 달성했다고 선언하지 않는다.
