종목표는 시장 왼쪽의 **관심그룹 · 종목표**에서 연다. 기존 차트 공간을 확보하기 위해 넓은 별도 표 창을 사용한다. 행을 고르면 기존 화면의 선택도 같은 코드로 바뀌고, 차트/리서치 이동 버튼으로 표를 닫고 선택 종목을 확인한다. 정렬이 기존 종목 배열의 인덱스를 바꾸지 않는다.

그룹 편입은 전체 관심 등록을 함께 수행한다. 그룹에서 제거하거나 그룹을 삭제해도 전체 관심과 노트는 유지한다. 전체 관심을 해제하면 모든 그룹의 해당 참조도 제거하고 노트는 남긴다. 한 종목은 여러 그룹에 속할 수 있다. 그룹 이름을 바꿔도 ID와 소속 종목은 유지한다.

표에는 가격 열을 두지 않았다. 따라서 잔고 조회가와 일봉 종가가 같은 열에 섞이지 않는다. 종목명·코드·시장·종류·보유 여부·조회 상태를 표시하고, 시장/종류를 확인할 수 없으면 `—`를 쓴다. 일봉 조회 중·실패·미지원·저장된 일봉 등은 기존 gateway 상태를 따른다. 표 행의 부가 설명에는 일봉 기준일과 잔고 관측 시각을 구분한다. 계좌 식별자가 충돌한 종목은 기존 연결 보류 규칙을 유지한다.

카탈로그에서 미등록 A를 차트 보기 → A 재선택 → B 선택할 때 A의 임시 표시가 지워지지 않던 원인은 A 재선택 시 임시 소유 표시를 잃는 것이었다. 기존 A를 다시 선택해도 관심/보유로 전환하지 않은 동안 `catalog_preview_code`를 유지하여 B 선택 시 A를 정리한다. 관심 또는 그룹에 편입한 A는 임시 종목으로 정리하지 않는다.

## 저장 계약

v3는 기존 필드를 유지하고 `watchlist_view`에 `groups`, `selected_group`, `sort`를 추가한다. 그룹 항목은 `id`, `name`, `codes`이며, 내장 그룹 ID는 `all`(전체 관심)과 `holdings`(보유)다. 사용자 그룹 ID는 이름과 별개다.

v1/v2를 읽을 때 메모리에서 이전하고 첫 정상 저장 때 원본 바이트를 `.bak`에 보존한다. 빈 관심목록은 기본 5종목으로 채우지 않는다. 기존 노트·종목명·명령서 초안·봉인 일지·시뮬레이션 계획·알 수 없는 필드를 보존한다. 저장 실패와 다른 프로세스의 변경 충돌은 기존 계약을 따른다. 그룹은 32개, 이름은 40자, 전체 관심은 1,000개 한도다.

### 검수 중 수정한 결함

- Godot `Tree`에 없는 스크롤바 API 호출을 제거하고 표시 중간 행을 기준으로 스크롤 위치를 복원한다.
- 실제 마우스 행 선택 이벤트 도중 차트 갱신이 표를 다시 만드는 재진입 오류를 발견했다. 입력 처리가 끝난 뒤 최신 선택 코드를 전달하도록 수정했다. 표에 초점이 있을 때도 Esc를 처리한다.
- 계좌와 종목 식별자가 충돌한 행이 보유 필터에서 숨겨지는 문제를 수정했다. 보유 목록에는 남기되 `확인 필요`로 표시하고 그룹 편입은 막는다.
- 긴 그룹 이름과 다중 소속의 텍스트가 창을 밀어내지 않도록 생략 표시와 전체 내용 툴팁을 사용한다.

### 실제 창과 재실행

60개 합성 종목과 격리 프로필을 사용하는 `watchlist_groups_review.gd`로 운영체제의 실제 Godot 창을 조작한다. 1280×720에서 만든 `창 검수 그룹`에 `300002`를 편입하고 코드 내림차순을 저장했다. 같은 종목 노트에 `1280 창 검수 · 그룹과 별개로 보존하는 노트`를 작성하고 프로세스를 종료한 뒤, 같은 저장본을 사용하는 새 1440×960 프로세스에서 그룹·소속·선택 그룹·정렬과 노트가 복원되는 것을 확인했다. 실제 창에서 생성한 저장본과 로그는 시스템 임시 폴더에만 둔다.

마지막 수정 후 두 크기를 각각 새 프로세스로 다시 실행했다. 실제 마우스로 표 행·코드 정렬 머리글·스크롤을 조작하고 Tree 초점에서 Esc로 닫았다. 선택 코드가 유지되며, 표와 버튼이 화면 안에 들어오고 겹침 없이 조작된다. `review1280-final.log`와 `review1440-final.log`에서 엔진 오류·스크립트 오류가 없음을 확인했다. 이전 재진입 오류가 포함된 중간 로그는 최종 통과 증거로 사용하지 않는다.

## 최종 검토와 커밋 범위

- v1/v2 원문을 읽기만 하는 이전 경로, v3 게시 전 원본 바이트 백업, 그룹 삭제 시 관심·노트·기존 작전 자료 유지 경로를 재검토했다. 이 부분의 추가 결함은 발견하지 않아 기존 검사를 반복하지 않았다.
- 최종 검토에서 B 행 클릭의 지연 전달 전에 A 종목의 시세 응답이 표를 갱신하면 B 선택이 사라지는 경합을 재현했다. 대기 선택 코드를 별도로 유지하여 단순 데이터 갱신·정렬·필터 재구성으로 덮어쓰지 않게 했다. 연속 클릭은 최신 선택만 전달하고 원본 행 삭제·창 닫기는 대기 선택을 취소한다.
- `watchlist_table_selection_race_test.gd`에서 수정 전 실패, 수정 후 통과를 확인했다. 기존 319건 전체는 반복하지 않았다. 참모 수정과 NH PLUG 작업을 제외한 Git 인덱스를 임시 폴더로 내보낸 커밋 대상 사본에서 이 선택 경합 검사와 영향을 받은 `watchlist_groups_ui_test.gd` 57건만 다시 실행했다. 두 검사와 사본 import가 오류 없이 통과했다. UI 크기나 저장 모델은 변경하지 않아 기존 창 검수와 저장 검증 기록을 유지한다.
- `origin`의 주소와 GitHub 메타데이터로 기존 비공개 `bigpine-choi/phalanx` 저장소임을 다시 확인했다. 대상은 `feature/watchlist-groups-table-v1`이며 일반 푸시를 사용한다.
- 커밋 메시지는 `feat: add watchlist groups and sortable table`이다. 이번 기능의 코드·테스트·문서·Godot UID만 선별한다. 기존 참모 수정 2개 파일과 검토 중 추가된 NH PLUG 관련 작업은 포함하지 않는다.
- 인증정보, 사용자 프로필, 실제 계좌 자료, 캐시, 임시 검수 로그는 커밋 대상에 없다.

## 직접 확인 순서

1. `PHALANX_WORKSPACE_PATH`, `PHALANX_CATALOG_CACHE`, `PHALANX_RESEARCH_CACHE`를 별도 임시 폴더 안의 경로로 지정하고 실행한다. 테스트 시 계좌·카탈로그·일봉·참모의 `PHALANX_*_OFFLINE=1`을 지정한다.
2. 시장 → 관심그룹·종목표 → 그룹 생성. 이름을 변경하고 동일 ID와 소속이 유지되는지 확인한다.
3. 전체 관심이나 보유 표에서 종목을 선택하고 서로 다른 사용자 그룹에 편입한다. 각 그룹으로 전환해 같은 종목을 확인한다.
4. 6개 열 머리글을 각각 두 번 눌러 정렬 방향이 바뀌어도 선택 코드가 같은지 확인한다. 스크롤 뒤 행 선택 → 차트 보기 또는 리서치·참모로 이동한다.
5. 그룹에서 종목을 제거하고 그룹을 삭제한 뒤 전체 관심과 노트가 남는지 확인한다. 종료 후 같은 프로필로 재실행해 그룹·선택 그룹·정렬·관심·노트를 확인한다.
6. 카탈로그에서 미등록 A를 차트 보기 → A 다시 보기 → B 보기 순서로 선택하여 임시 A가 남지 않는지 확인한다.

실시간 시세표·가격 정렬·관심 그룹 간 드래그·다중 행 일괄 편집·미보유 종목 배분 편입은 이번 범위에 포함하지 않는다. 타 PC의 WSL 환경과 실제 API는 이번 변경에서 재검증하지 않는다.
